# スポット実績パック候補カタログ

スポット訪問実績（landmark spots）で採用しうる「パック」の候補と、採用可否の判断基準をまとめる。
機能そのものの仕様は別途の設計ドキュメントに記載し、ここでは**何をパックにするか**の検討材料だけを扱う。

初回ラインナップに入らなかった候補も、将来の追加ネタとして残す。

## 1. パックとは

パックは、スポット訪問実績における「コレクションの単位」である。

- パックは複数のスポットを持つ
- スポットごとに到達半径と必要滞在時間を持つ
- パック内の全スポットへ到達すると「完走実績」が解除される
- パックは将来の買い切りIAPの単位にもなりうる（実績の粒度と販売の粒度は分離する。細かく刻んだパックを、売るときだけ束ねてよい）

## 2. 完走トロフィーの運用ルール

パックの内容が後から変わると、完走トロフィーの扱いが破綻する。以下を運用ルールとする。

### ルール1: 解除済みの完走実績は、リストが変わっても取り消さない

既存の実績システムは `INSERT OR IGNORE` のみで解除の取り消し経路を持たない（`src/features/achievements/achievementRepository.ts`）。
「一度解除した実績は取り消さない」はアプリ全体の不変条件であり、スポット実績もこれに従う。

### ルール2: スポットを削除するときは、マスタから消さず `retired` を立てる

完走判定の分母からは外し、一覧では「現存せず」と表示する。到達済みユーザーの訪問記録は残す。

分母が減っても矛盾は起きない。達成済みユーザーはルール1で影響を受けず、未達成ユーザーは達成しやすくなるだけである。
現存天守が戦災と火災で20前後から12へ減った経緯のように、「減る」は現実に起こりうる。

### ルール3: 既存パックにスポットを追加しない

「12/12で完走済み」が翌アップデートで「12/13」になると表示が矛盾する。
パックは**発行時点で内容を確定した不変のコレクション**として扱い、内容変更は新パックの発行でのみ行う。

なお、座標・到達半径・必要滞在時間の修正はメンバー変更ではないため、いつでも自由に行える
（訪問記録は安定文字列の `spot_id` で紐づくため壊れない）。

### ルール4: パックの全メンバーが現実的に到達可能であること

1つでも到達不能なメンバーが混ざると、完走トロフィーが永久に解除されないパックになる。
選定時に全メンバーの到達可能性を確認する。

## 3. 採用可否の判断基準

| 基準                 | 内容                                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------------------- |
| 不変性               | リストが増減しないこと。**名称に件数が含まれるリストは構造的に増えない**（三景、十二城、百観音など） |
| 異説がないこと       | 定説が1つに定まっていること。複数説が併存するリストは採用しない                                      |
| 座標で定義できること | 「地域」「文化」ではなく、施設・地点として到達点を定義できること                                     |
| 到達可能性           | ルール4。全メンバーへ現実的に到達できること                                                          |
| 全国分散             | 一都市に固まっていないこと。固まっていると「ついで」で埋まり価値が下がる                             |
| 難易度の階層         | 日常で埋まるパックから一生かけるパックまで揃っていること                                             |
| 権利                 | 選定主体の権利・商標を確認すること（第6節）                                                          |

## 6. 権利・ライセンスの整理

| 種別                                                   | 扱い                                                         |
| ------------------------------------------------------ | ------------------------------------------------------------ |
| 地理的事実（端、標高順、県庁所在地）                   | 選定主体が存在しない。権利問題なし。**最も安全**             |
| 慣用の「三大○○」                                       | 選定主体が存在しない。権利問題なし                           |
| 官公庁の選定（名水百選、音風景100選など）              | 政府標準利用規約準拠。出典明示で利用可                       |
| 民間団体の選定（日本100名城、滝百選、さくら名所100選） | 選定行為に創作性が認められる余地がある。地名の列挙自体は事実 |

### 6.1 座標データの出所

座標は**自分で地図を確認して手入力する**方針とする。理由は以下。

- 到達半径と必要滞在時間はスポットごとに調整するため、どのみち1件ずつ地図で確認する工程が必要であり、座標だけ機械取得しても得が小さい
- OpenStreetMap（ODbL）や Wikipedia（CC BY-SA）から抽出すると、継承義務と帰属表記が発生し、スポットデータ自体がそれらのライセンス下に置かれうる
- 国土地理院データを使う場合は出典明示で利用できるが、大規模リストを扱う段階で改めて検討する

### 6.2 日本百名山の注意

「日本百名山」は深田久弥の1964年の著作による選定であり、著者の没年（1971年）から日本の保護期間は2041年まで存続する。
山名そのものは事実だが、「この100座を選んだ」という選定行為に創作性が認められる余地があり、商用アプリでリストと名称をそのまま使うことには理論上のリスクがある。

対応の選択肢は3つ。

1. そのまま実装する（登山系アプリでの実務慣行に乗る）
2. **「日本の高峰100」など独自選定・独自名称にする**（標高上位100座なら完全に事実ベース）
3. 百名山は採用せず、公的選定の「日本の滝百選」などに替える

推奨は2。権利問題が完全に消え、「都道府県最高峰」など他の事実ベースパックとも整合する。

### 6.3 商標

「日本100名城」は公益財団法人日本城郭協会の登録商標。
**リスト内容の利用と名称の商標使用は別問題**であり、採用する場合は名称の扱いを確認すること。

## 7. 将来拡張: 高速道路の走破率実績

全線開通済み（延伸予定のない）高速道路の走破率を実績にする構想がある。**v1.3.0 では対象外**。

**判定はIC（インターチェンジ）にスポットを置いて行う。** ICへ立ち寄った＝通過したとみなし、
隣接する2つのICへの到達から区間の走破を導出する。路線の形状（ポリライン）は持たない。

この方針により、スポット実績の仕組みがほぼそのまま流用できる。

|              | スポット実績             | 高速道路走破率                         |
| ------------ | ------------------------ | -------------------------------------- |
| マスタデータ | 点（中心座標＋半径）     | 同じく点（ICの座標＋半径）             |
| 判定         | 点との距離＋滞在時間     | 同じ判定を滞在時間0相当で使う          |
| 達成         | 到達した / していない    | 走破率 0〜100%（パーセント表示）       |
| 画面         | 一覧行＋パック詳細子画面 | 子画面を作らず既存の実績グリッドを使う |

設計時の検討事項。

- 高速走行時の取りこぼし。時速100kmでは28m/s進むため、半径300mのICでも通過は約20秒しかない。GPS観測間隔によっては半径内に1点も入らない可能性がある
- 区間走破の定義。隣接IC両方への到達を条件にすると、別々の機会にそれぞれのICへ立ち寄っただけでも走破と判定されうる
- IC付近は一般道も近接するため、並走区間での誤判定を避ける条件が必要になりうる
- 「延伸予定がない」ことがパック選定の条件になる点はスポット実績のルール3と同じ思想

詳細は `docs/superpowers/specs/2026-09-23-landmark-spot-achievements-design.md` 第12節を参照する。

## 8. 初回ラインナップ
