# 年間振り返りストーリー（年次レポート）設計

## 1. 目的と背景

1年分の記録を、インスタグラムのストーリーのような全画面ページ送りで振り返れる機能を追加する。

- 主目的は **ユーザー自身が1年を懐かしむこと**。そのうえで、インスタなどへ共有しやすくする。
- 年末の振り返りの時期に合わせ、期間限定で公開する。
- **無料ユーザーも閲覧できる**（Plus限定にはしない）。アプリの価値を感じてもらう機会として扱う。
- `docs/plus-features.md` §5.4・§5.7〜5.9 にある既存の年次レポート構想は参考程度とし、本書の内容を正とする。本機能の実装時に、同ドキュメントの年次レポート部分を本書に合わせて更新する（Plus限定ではなくなる）。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール

- 1ページ1項目の全画面ストーリーを、7秒ごとに自動で送り、最後にサマリーを表示する。
- 各ページに入場アニメーションを付け、ページ間はトランジションでつなぐ。
- 集計結果をJSONで保存し、画面を開くときに重い集計をしない。
- 集計が終わったら、Push通知（ローカル通知）でお知らせする。通知をタップすると、ストーリーを直接開く。
- 公開期間中は、地図画面に「ふりかえり」ボタンを「あとn日」バッジ付きで表示する。
- 共有するときは、プライベートな滞在場所を隠すかどうかを確認する。

### 非ゴール

- ストーリー全体の動画・GIF保存（従来方針どおり対象外）。
- 公開期間外（1月16日以降）の閲覧。過去の年のレポートを見返す機能は作らない（JSONは残す）。
- 写真ジオタグを使ったページ（共有時に写真そのものが外部へ出る懸念があるため外す）。
- GPS記録処理（バックグラウンド位置タスク）への変更。

### アンチゴール

- 集計中にアプリが固まる、または地図操作が引っかかる。
- GPS記録の信頼性に少しでも影響する。
- プライベートな滞在場所が、ユーザーの意図に反して共有画像に写る。
- 記録がほとんどない人に、空っぽのレポートを見せる。

## 3. 期間と対象年

| 項目           | 値                                                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 集計期間       | 対象年の 1月1日 〜 12月15日（端末ローカル日付 `local_date` 基準）                                                                                                |
| 集計開始       | 12月16日〜翌年1月15日の間にアプリが前面になり、対象年のレポートが未完了のとき（1月に初めて開いた人も前年分を集計してボタンを出す。通知は出さない）【設計者判断】 |
| 公開期間       | 12月20日 0:00 〜 翌年1月15日 23:59（端末ローカル時刻）                                                                                                           |
| 対象年の決め方 | 12月20日〜31日に開いた場合はその年、1月1日〜15日に開いた場合は前年                                                                                               |

- オープニングページに `集計期間 YYYY/1/1〜12/15` を小さく表示する。12月後半の記録が入っていないことを明示するためである。
- 文言は「今年」「去年」を使わず、`2026年` のように年を数字で書く。12月にも1月にも見られるためである。

## 4. ページ構成と文言

1ページ7秒で自動送りする（10ページで約70秒）。`YYYY` は対象年、その他の大文字は集計値。

- ページ6の「いちばん遠くまで出かけた日」は、集計期間内で**その日の移動距離（`daily_logs.distance_meters`、欠けている日はポイントから計算）が最大の日**とする。同じ距離の日が複数あれば、早い日付を採る。
- 以下のページは、値が0件のとき**ページごと飛ばす**。サマリーの該当タイルも出さない。そのため、ページ数は可変（最小7ページ）になる。
  - ページ7: 初訪問の都道府県・市区町村がどちらも0
  - ページ8: 新しく塗ったエリアが0
  - ページ9: 解除した実績も到達したスポットも0（スポットだけ0なら、スポットなしの文言を出す）

| --- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |

### 4.1 比較対象（ページ3）

総移動距離を基準距離で割り、1以上になるいちばん大きい単位を使う。1,000km未満のときは、東京〜大阪の小数（例 `0.4往復分`）にする。値は小数1桁。

| 地球〜太陽             | 299,200,000 km | 地球〜太陽 n往復分 |
| 地球〜火星（最接近時） | 112,000,000 km | 地球〜火星 n往復分 |
| 地球〜月               | 768,800 km     | 地球〜月 n往復分   |
| 地球1周                | 40,075 km      | 地球 n周分         |
| 日本1周                | 12,000 km      | 日本 n周分         |
| 日本縦断               | 3,000 km       | 日本縦断 n回分     |
| 東京〜大阪 往復        | 1,000 km       | 東京〜大阪 n往復分 |

### 4.2 距離の段階（ページ4・10）

| 段階 | 年間距離         | ページ4                        | ページ10                           |
| ---- | ---------------- | ------------------------------ | ---------------------------------- |
| 1    | 3,000km未満      | このエリアを移動しました！     | いろいろなところに行きましたね！   |
| 2    | 3,000〜10,000km  | いろんなところに行きましたね！ | `YYYY`年もいっぱい移動しましたね！ |
| 3    | 10,000〜25,000km | 旅行が多い一年でしたね！       | 旅行が多い一年でした！             |

境目は、電車通勤（往復40km × 約240日 ≒ 1万km）だけで上位の段階に入りにくいように置いた。

## 5. ストーリー画面の振る舞い

- 全画面・ダーク基調の固定ビジュアル（OSのライト/ダークに関係なく固定。共有時の見栄えを優先する）。
- 上部に、表示するページ数で分割したプログレスバーを置き、左上にアプリアイコン・`Strollia`・`Report YYYY` のヘッダー、右上に閉じるボタン、右下に共有ボタンを置く。
- 1ページ7秒で自動的に次へ送る。最後のページでは止まり、閉じるまで表示し続ける。
- 画面の右側をタップすると次へ、左側をタップすると前へ移動する。押しっぱなしにすると一時停止する（ページ内アニメーションと進行バーの両方を止める）。
- ページ間のトランジションは「ズーム＋ぼかし」：入ってくるページは拡大＋ぼかしから元のサイズへ、出ていくページは縮小＋ぼかしで消える。React Native でぼかしの再現が重い、または難しい場合は、拡大縮小＋フェードを優先し、ぼかしは省略してよい（ビルダー判断）。
- アプリが背面に回ったら一時停止し、前面に戻ったら再開する。
- 参考デモ: `.superpowers/brainstorm/63445-1795520337/content/year-story-v5.html`（git管理外のブラウザ試作）。

## 6. 共有

- 共有ボタンは、**表示中のページ**をPNG画像にしてOS標準の共有シートへ渡す（既存の `src/features/export/capturedViewShare.ts` の仕組みを使う）。
- 地図を含むページ（4・6・10）で、共有範囲内に「共有時に隠す範囲」を設定した有効な滞在場所が含まれる場合は、共有シートの前に確認ダイアログを出す。
  - タイトル: `プライベートな滞在場所を隠しますか？`
  - 説明: このページには「共有時に隠す」設定の滞在場所が含まれています。隠すと、その範囲内のルートは共有する画像に表示されません。
  - ボタン: `隠して共有` / `隠さずに共有` / `キャンセル`
- 含まれない場合は、確認せずに共有シートを開く。
- 「隠して共有」では、既存の `toPrivacyRouteSegments`（`src/features/stayPlaces/privacyRouteSegments.ts`）と同じ規則で、範囲内の点と範囲を横切る線分を除外して描いた画像を共有する。
- **既存の共有（日別・GIF・月次）は確認なしで必ず隠している**が、このストーリーでは「隠さずに共有」も選べる。ユーザーの決定による意図的な違いであり、`docs/stay-places.md` に追記する。
- 滞在場所を読み込めない場合は、既存方針どおり共有を開始せずにエラーを表示する。
- 共有中・ダイアログ表示中は、自動送りを一時停止する。

## 7. 集計とJSON保存

### 7.1 方針（案Aを採用）

アプリが前面にある間だけ、小さなステップに分けて集計する。GPSのバックグラウンド処理には一切手を入れない。

- 12月16日以降、アプリが前面にあり、起動初期化が終わってから、操作が落ち着いたとき（`InteractionManager.runAfterInteractions` など）に1ステップずつ進める。
- 1ステップは「1か月分の集計」程度の小さな単位とし、ステップの間でUIスレッドへ制御を返す。
- 進捗（どの月まで終わったか、途中の集計値）は保存し、アプリが終了しても続きから再開できるようにする。
- 数値は SQLite の集計（SUM / COUNT / MIN / MAX / GROUP BY）で出す。GPSポイント全件をJSへ読み込まない。
- 地図用のルート（ページ4・6・10）は、点を間引いて保存する（目安: 年間マップ最大2,000点、最遠日のルート最大500点）。間引きは月ごと・日ごとのステップの中で行う。
- 集計中にエラーが出たら、そのステップを捨てて次の機会にやり直す。ユーザーへのエラー表示はしない（Sentryへ記録する）。

### 7.2 保存先

新しいテーブル `annual_reports` を追加する。

| カラム                      | 型                  | 説明                                                     |
| --------------------------- | ------------------- | -------------------------------------------------------- |
| `year`                      | INTEGER PRIMARY KEY | 対象年                                                   |
| `payload_version`           | INTEGER NOT NULL    | JSONの形式バージョン。年ごとに中身が変わることを想定する |
| `status`                    | TEXT NOT NULL       | `in_progress` / `completed`                              |
| `progress_json`             | TEXT NULL           | 途中の進捗・中間集計値                                   |
| `payload_json`              | TEXT NULL           | 完成したレポート本体（`completed` のとき必須）           |
| `notification_scheduled_at` | TEXT NULL           | 通知を予約した日時（重複予約を防ぐ）                     |
| `created_at` / `updated_at` | TEXT NOT NULL       |                                                          |

- 表示内容が毎年変わる可能性があるため、レポートの中身はカラムに分けずJSONで持つ。表示側は `payload_version` を見て解釈する。
- 一度 `completed` になったレポートは、あとからGPXをインポートしても再計算しない（公開期間中の数字を固定する）。
- 1月16日以降もJSONは削除しない（将来の見返し機能の余地を残す）。

### 7.3 JSONの中身（payload_version 1）

ビルダーが型として定義する。最低限、以下を含む。

- 対象年、集計期間（開始日・終了日）
- 記録日数、日別の記録有無（365日分。カレンダー表示用）
- 総移動距離（m）
- 月別移動距離（12か月分）
- 1年分の間引き済みルート（複数の線。日をまたぐ線を1本につながないよう、日単位で区切る）
- 最遠日（移動距離が最大の日）: 日付、間引き済みルート（各点の時刻付き）、その日の移動距離
- 初訪問の都道府県一覧・市区町村数（`visited_admin_areas.first_visited_at` が集計期間内のもの）。都道府県チップの表示用に、その年に訪れた都道府県一覧も含める
- 新しく塗ったエリア数（`visited_cells.first_visited_at` が集計期間内）、表示用のサンプル（前年までのエリアとの比率など）
- 解除した実績数と代表3件（`achievement_unlocks`）、到達したスポット数と代表（`landmark_spot_visits`）

距離は、既存の日別ログ（`daily_logs.distance_meters`）を優先し、欠けている日だけポイントから計算する（月次レポートと同じ方針）。

### 7.4 レポートを作らない条件

集計期間に記録のある日が **7日未満** の場合は、レポートを作らない。通知も地図のボタンも出さない。中身がほとんどないレポートを見せないためである。

## 8. 通知

- タイトル: `今年をふりかえりませんか？`
- 本文: `YYYY年の年間レポートを作りました！`
- 集計が終わった時点で、以下のルールで予約する（ローカル通知）。
  - 12月16日〜19日に完了した場合: 12月20日 9:00 に予約する。
  - 12月20日以降に完了した場合: 通知は出さない（ユーザーはアプリを開いているので、地図のボタンで気づける）。
- 通知の権限がない場合は予約しない。この機能のために権限をリクエストしない。
- Android は専用の通知チャンネル（例 `annual-reports`、名前「年間レポート」）を使う。
- 通知データに `screen: 'annualReport'` と `year` を入れ、タップしたらストーリー画面を直接開く。既存の `useMonthlyReportNotificationResponse` と同じ作り（初期化完了待ち・重複処理ガード）にする。
- 公開期間外にタップされた場合は、ストーリーを開かず地図を表示する。
- 無料ユーザーにも通知する。

## 9. 地図画面のふりかえりボタン

- 公開期間中、かつ対象年のレポートが `completed` のときだけ表示する。
- 「ふりかえり」ボタンに `あとn日` のバッジを付ける。`n` は公開終了日（1月15日）までの残り日数（終了日当日は `あと1日`。ビルダーが境界を決めてテストで固定する）。
- タップするとストーリーを開く。
- 配置は既存の地図UI（`MapBottomDashboard` / `SpeedDial` など）との兼ね合いで、ビルダーが `DESIGN.md` に沿って決める。新しい部品が必要な場合は、汎用名の1ファイル1コンポーネントにする（例: バッジ付きボタン）。

## 10. 画面構成とナビゲーション

- ルートは `src/app/annual-report.tsx`（トップレベル）。月次レポートと同様に、地図から開くトップレベル画面として扱う。
- 画面本体は `src/ui/components/` に置き、状態と操作は `AppStateProvider` から `useAppState()` で受け取る。
- Sentry の画面名マッパー（`pathnameToScreenMode` など）に新しいパスを追加する。
- ストーリー専用の見た目（各ページ）は、ストーリーの外では使わない専用コンポーネントになる。月次レポートが `src/ui/components/reports/` に専用部品を置いている前例に合わせ、`src/ui/components/annualReport/`（仮）にまとめる。プログレスバーやタップ送りなどの汎用部分は、汎用名で切り出す。

## 11. 検討した案

集計をいつ・どこで行うかについて、3案を検討した。

| 案            | 内容                                                          | 評価                                                                                                                  |
| ------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **A（採用）** | アプリが前面にある間に、ステップ分割で集計                    | GPS記録に触れずに済む。16〜20日にアプリを開かなかった人には通知が届かないが、次に開いたときに集計してボタンで知らせる |
| B             | Aに加え、GPS記録のバックグラウンド処理でも1ステップずつ進める | 通知の到達率は高いが、GPS記録処理に手を入れることになり、ユーザーが不安視したため不採用                               |
| C             | OSのバックグラウンド処理（expo-background-task）を新しく導入  | 依存とネイティブ設定が増える。iOSでは実行タイミングをOSが決めるため、期日に合わせにくい。不採用                       |

## 12. 未決事項・ビルダーに任せる点

- ズーム＋ぼかしトランジションの実装方法（ぼかしを省略してよいかの判断を含む）。
- 地図ページの描画方法（`react-native-maps` を使うか、ストーリー用に簡易描画するか）。共有画像の見栄えと、描画負荷のバランスで決める。
- ふりかえりボタンの配置とデザイン。
- 間引きアルゴリズムと点数の上限。

## 13. テスト方針

- 純粋関数（比較対象の選択、距離の段階判定、公開期間・残り日数・対象年の判定、通知予約日時の決定、JSONの組み立て・間引き）を単体テストする。
- `annual_reports` リポジトリを、`db` のモックでテストする。
- 集計のステップ実行（途中再開、エラー時のやり直し、完了時の通知予約）を、モックでテストする。
- ストーリー画面の重要な振る舞い（タップ送り、一時停止、共有時の確認ダイアログの出し分け）を RTL でテストする。
- 通知タップから画面を開く処理を、フックのテストで確認する。
