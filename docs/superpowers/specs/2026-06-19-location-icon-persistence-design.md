# 現在地アイコン永続化 設計

## 背景

現在のカスタム写真アイコンは、`expo-image-picker` が返した一時ファイルURIをそのままSQLiteへ保存している。一時ファイルはアプリ更新やOSのキャッシュ削除で読めなくなる可能性があり、画像読込エラーが起きると選択値までOS標準へ書き換えている。

また「さんぽ」「コンパス」「カスタム」はStrollia Plus限定であるため、起動直後にPlus状態が未確定の間はOS標準として解決される。保存値は残っていても、更新後の初回起動などで設定が戻ったように見える。

## 目的

- アプリ更新後も、選択済みの「さんぽ」「コンパス」「カスタム写真」を維持する。
- カスタム写真を写真ライブラリから削除しても、現在地アイコンとして利用し続けられるようにする。
- 一時的な画像読込失敗によって、保存済み設定をOS標準へ書き換えない。
- 別のカスタム写真を選んだ場合は、安全に新しい画像へ置き換える。

## 対象外

- 複数のカスタム写真を履歴として保持する機能。
- カスタム写真の編集、再クロップ、クラウド同期。
- Strollia Plusの利用可否判定ルールの変更。

## 設計

### 1. カスタム写真の永続保存

`src/features/customization/customIconStorage.ts` を追加し、カスタム写真ファイルの保存、旧形式からの移行、削除、表示URIの解決を担当させる。

写真選択後はImagePickerのURIを直接保存せず、`expo-file-system/legacy` を使ってアプリのdocument領域配下にある専用ディレクトリへコピーする。SQLiteにはアプリコンテナの絶対URIではなく、管理対象ファイル名を保存する。起動時には現在のdocument領域とファイル名から表示URIを組み立てる。これにより、アプリ更新でコンテナの絶対パスが変わっても追従できる。

ファイル名は選択ごとに一意にする。新しい写真を選んだ場合は、次の順序で置き換える。

1. 新しい写真を新しい管理ファイルへコピーする。
2. 新しいファイル名をSQLiteへ保存する。
3. UIを新しい写真へ切り替える。
4. 以前の管理ファイルを削除する。

コピーまたは設定保存に失敗した場合は、新しい一時管理ファイルだけを削除し、以前の写真と設定を維持する。古いファイルを先に削除しない。

### 2. 旧URIの移行

既存の `customIconImageUri` が絶対URIの場合は旧形式として扱う。起動時にファイルが読み込める場合は、document領域へコピーして新しい管理ファイル名へ設定を更新する。

旧URIの存在を確認できてもdocument領域へのコピーに失敗した場合は、部分ファイルを掃除したうえで、そのセッションでは読み取れる旧URIを表示する。SQLiteの旧参照は変更せず、移行失敗として警告を記録する。

旧URIがすでに無効な場合は、OS標準へ設定を書き換えない。画面上は安全のためOS標準を表示するが、`userLocationIcon = custom` と旧URIは保持する。ユーザーが新しい写真を選択すれば通常の置き換え処理で復旧できる。

### 3. 画像読込失敗時の非破壊フォールバック

`MapScreen` の画像読込エラーでは、現在の `clearCustomIcon()` のようにSQLiteを書き換えない。セッション内だけOS標準表示へフォールバックし、保存済みのアイコンIDとファイル名は維持する。

同じ壊れたURIを再描画してエラーを繰り返さないよう、App側にセッション内の画像エラー状態を持たせる。新しい写真を選択した場合はエラー状態を解除する。

### 4. Plus状態確定後の表示

起動時の初期化処理で、保存済みアイコン設定とPlus状態を両方解決してからアプリを描画可能にする。ただしRevenueCatが応答しない場合にGPS記録やアプリ全体を無期限に止めないよう、初回取得には待機上限を設ける。

待機上限を超えてもPlus状態が未確定の場合は、以前から保存されている「さんぽ」「コンパス」「カスタム写真」だけを未確定期間中も表示する。これはアプリ更新・起動時に選択が戻ったように見せないための表示継続ポリシーであり、Plus利用資格の確認や付与ではない。新しいPlusアイコンの選択、アプリカラー、レポート、ペイウォールなど、現在地アイコン表示以外のPlus判定には適用しない。

RevenueCatがPlus無効と確定した場合は直ちにOS標準を表示するが、保存済みの選択値は削除しない。Plus有効と確認できた場合は保存済みの選択を維持する。待機上限後に初回取得が遅れて完了した場合も同様に確定状態へ切り替え、より新しい購読更新が届いている場合は古い初回取得結果で上書きしない。

RevenueCatの設定・通信・CustomerInfo取得が失敗した場合はPlus無効が確認されたとは扱わず、未確定状態を維持する。明示的にinactiveを取得できた場合だけ無効確定として保存アイコンの表示継続を終了する。

初期化中にAppがアンマウントされた場合は待機タイマーを解除し、DB・位置情報の読み込み結果や自動記録完了を含む残りの初期化によるstate更新や副作用を進めない。

### 5. ユーザー向け表示

写真はアプリ管理領域へ複製されるため、選択完了後の「写真をアルバムから削除するとOS標準に戻ります。」Alertは削除する。

写真選択、コピー、設定保存のいずれかに失敗した場合だけ、既存の写真が維持されたことが分かるエラーAlertを表示する。

## データフロー

### 新しい写真を選択

`ImagePicker` → 永続領域へコピー → SQLiteへ管理ファイル名を保存 → UI切替 →旧管理ファイル削除

### 起動時

SQLiteからアイコンIDと保存値を取得 → 旧絶対URIなら移行 → 管理ファイル名から現在のURIを解決 → Plus状態を待機上限まで確認 → 確定済み、または保存アイコンだけを継続表示する未確定状態で地図を表示

### 画像読込エラー

`Image.onError` → セッション内フォールバック状態をON → OS標準表示

この経路ではSQLiteを更新しない。

## テスト方針

- ImagePickerの一時URIがdocument領域へコピーされ、絶対URIではなく管理ファイル名が返ること。
- 旧絶対URIを読み込める場合に新形式へ移行できること。
- 旧絶対URIが読めない場合に設定削除を要求しないこと。
- 新しい写真の保存成功後にだけ旧管理ファイルを削除すること。
- 新しい写真の保存失敗時に旧管理ファイルを削除しないこと。
- 画像読込エラー時に永続設定を書き換えず、セッション内だけOS標準表示へ切り替えること。
- Plus状態の解決前に地図を描画可能状態へ進めないこと。
- Plus状態が待機上限を超えた場合、保存済みPlusアイコンだけを維持し、他のPlus機能を開放しないこと。
- 遅延した初回取得または購読更新で確定した状態へ切り替わること。
- 初期化中のアンマウントで待機タイマーと残りの初期化を中止すること。
- 「さんぽ」「コンパス」「カスタム」の保存済み選択がPlus有効確認後に復元されること。
- 写真選択成功時に旧Alertが表示されないこと。

## 完了条件

- アプリ更新後も、Plusが有効または確認待ちなら選択済みの現在地アイコンが表示継続される。
- カスタム写真は写真ライブラリから削除しても表示できる。
- 別の写真を選択すると新しい写真へ置き換わり、不要な旧管理ファイルが残らない。
- 一時的な画像読込失敗では保存済み設定が消えない。
- 型チェックと全テストが成功する。
