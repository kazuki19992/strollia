# フォアグラウンド限定位置情報記録デザイン

## 目的

位置情報のフォアグラウンド権限は付与されているが、バックグラウンド権限は付与されていないユーザーについて、画面表示と実際の記録動作を一致させる。

設定画面では現在、この状態を「アプリ起動中のみ記録」と案内している。しかし、実際のGPSログ、Visited Grid、実績処理はバックグラウンド位置情報タスク内にしかなく、フォアグラウンド監視はカスタム現在地アイコンの表示にしか使われていない。そのため、該当ユーザーの位置情報は保証して保存されない。

本修正では、「アプリ起動中」をアプリがフォアグラウンドで操作可能な状態と定義する。フォアグラウンド権限だけがある場合は、その間だけ位置情報を取得・保存し、アプリが非アクティブまたはバックグラウンドになった時点で監視を解除する。

## 成功条件

- フォアグラウンド権限のみのユーザーは、アプリがフォアグラウンドの間だけGPSログがSQLiteへ保存される
- 同じ位置更新からVisited Gridと実績処理も更新される
- アプリが非アクティブまたはバックグラウンドの間は、Strolliaの前景監視による位置取得・保存を行わない
- バックグラウンド権限があるユーザーは、従来どおりバックグラウンドタスクから保存される
- バックグラウンド記録とフォアグラウンド限定記録が同時に保存処理を行わない
- OS標準とカスタムのどちらの現在地アイコンを選択していても、フォアグラウンド限定記録が動作する
- 常時許可からフォアグラウンド許可のみに変更した場合、以前のバックグラウンドタスクを残さない
- カスタム現在地アイコンの表示・追従挙動を維持する
- 常時記録モードでは、カスタム現在地アイコン利用時もバックグラウンドタスクを重複登録せず、前景位置監視から二重保存しない

## 用語

- **常時記録モード**: フォアグラウンド権限とバックグラウンド権限の両方がある状態
- **フォアグラウンド限定記録モード**: フォアグラウンド権限はあるが、バックグラウンド権限がない状態
- **権限なし**: フォアグラウンド権限がない状態
- **アクティブ**: React Nativeの `AppState` が `active` の状態

## 検討した方式

### 採用: 1つの前景位置監視を表示と保存で共有する

既存の前景位置監視を、カスタムアイコン表示専用ではなく、前景の位置更新を一元的に扱うフックへ拡張する。

カスタムアイコン表示またはフォアグラウンド限定記録のどちらかが必要な場合に、1つだけ `Location.watchPositionAsync` を開始する。位置更新は、必要に応じて画面表示用コールバックと共通保存セッションへ渡す。

利点:

- カスタムアイコン利用時も位置監視が重複しない
- 位置監視の開始・解除条件を一か所で管理できる
- 既存の現在地表示を維持しながら保存を追加できる

注意点:

- 表示用と記録用で必要精度が異なるため、記録中は記録要件を優先した監視設定を使う
- 非同期保存が重ならないよう直列化が必要になる

### 不採用: 保存専用の前景位置監視を追加する

既存のカスタムアイコン用監視を残し、フォアグラウンド記録専用の監視を追加する方式。

実装責務は分かりやすいが、カスタムアイコン利用時に2つの `watchPositionAsync` が同時に動作する。端末の位置取得とコールバックが重複し、電池消費、競合、テスト対象が増えるため採用しない。

### 不採用: バックグラウンドタスクをフォアグラウンド権限だけで利用する

既存のバックグラウンドタスクを開始し、OSがフォアグラウンド中だけ更新を配送することへ依存する方式。

iOS・Android間の権限とタスク継続条件の差が大きく、「アプリがフォアグラウンドの間だけ」という境界をStrollia側で保証できない。既存の不具合と同じくOSや登録状態に依存した動作になるため採用しない。

## 状態別の動作

| 権限状態             | AppState              | バックグラウンドタスク | 前景位置監視           | 保存元                     |
| -------------------- | --------------------- | ---------------------- | ---------------------- | -------------------------- |
| 常時記録             | active                | 開始または継続         | カスタムアイコン時のみ | バックグラウンドタスクのみ |
| 常時記録             | inactive / background | 継続                   | 解除                   | バックグラウンドタスクのみ |
| フォアグラウンド限定 | active                | 停止                   | 開始                   | 前景位置監視のみ           |
| フォアグラウンド限定 | inactive / background | 停止                   | 解除                   | 保存しない                 |
| 権限なし             | 全状態                | 停止                   | 解除                   | 保存しない                 |

`inactive` は通知センター、着信、画面遷移などで一時的に操作不能になる状態を含む。記録範囲を明確にするため、`active` 以外では前景位置監視を解除する。

## アーキテクチャ

### 位置情報保存セッション

`backgroundLocationTask.ts` に直接記述されている保存処理を、前景・背景から共用できる位置情報保存セッションへ移す。

セッションは初期化時にDBから最新の保存済みGPSポイントを1回取得し、処理中の `previousSavedPoint` と `previousVisitedCellPoint` をメモリ上で保持する。その後、`Location.LocationObject[]` を受け取り、現在と同じ順序で以下を実行する。

1. DBを初期化する
2. 最新の保存済みGPSポイントを取得する
3. 各 `LocationObject` を `LocationPoint` へ変換する
4. 前回位置との間を補間し、Visited Gridをupsertする
5. 精度・距離・時系列の保存判定を行う
6. 保存対象のGPSポイントをSQLiteへ追加する
7. GPSポイント保存後に実績処理を行う

手順1と2はセッション開始時に1回だけ行う。フォアグラウンド監視から位置情報が1件ずつ渡されても、コールバックごとに `getLatestLocationPoint()` を実行しない。保存に成功したGPSポイントを `previousSavedPoint`、Visited Grid処理に使用した最新位置を `previousVisitedCellPoint` として更新し、次のコールバックの距離・時系列判定へ引き継ぐ。

セッションはUI、AppState、権限状態、Expo TaskManagerを参照しない。渡された位置情報を既存ルールで永続化することだけを責務とする。

バックグラウンドタスクはタスク呼び出しごとにセッションを作成し、受信した配列を一括処理する。前景位置監視は監視開始時にセッションを1つ作成し、監視が有効な間は同じセッションへ位置情報を1件ずつ渡す。監視を解除した場合はセッションを破棄し、次回開始時にDBの最新点から再初期化する。

保存処理が途中で失敗した場合は、メモリ上の前回点とSQLiteの状態がずれる可能性がある。そのセッションを破棄し、次の位置更新時にDBから最新点を再取得してから処理を再開する。

### 前景位置監視フック

既存の `useForegroundUserLocation` は、用途を表す入力を受け取る前景位置監視フックへ拡張する。責務は以下とする。

- 有効時にフォアグラウンド権限を確認する
- 最終取得位置を画面表示へ反映する
- `Location.watchPositionAsync` を1つだけ開始する
- 新しい位置更新を画面表示へ反映する
- フォアグラウンド限定記録モードの場合だけ、新しい位置更新を保存セッションへ渡す
- 無効化またはアンマウント時に購読を解除する
- 位置更新ごとの保存処理を直列化する
- 監視開始または保存失敗をAppへ通知する

最終取得位置は古い観測値である可能性があるため、現在地表示の初期化だけに使用し、GPSログやVisited Gridには保存しない。

保存処理はPromiseチェーンで直列化する。前の更新のSQLite・実績処理が完了する前に次の更新が届いても、セッションの前回点更新とSQLiteへの挿入が並行しないようにする。購読解除前に受信済みの位置は、その取得時点が `active` であれば保存を完了させる。

### 監視設定

表示だけに使う場合は、現在の挙動を維持する。

- `accuracy: Location.Accuracy.Balanced`
- `distanceInterval: 5`
- `timeInterval: 2_000`

フォアグラウンド限定記録を行う場合は、GPSログの品質を優先する。

- `accuracy: Location.Accuracy.High`
- `distanceInterval: 5`
- `timeInterval: 2_000`

カスタムアイコンと記録を同時に使う場合も監視は1つとし、後者の設定を使う。2秒はカスタムアイコンの現在地表示応答性を維持するための要求間隔であり、全コールバックのSQLite保存を意味しない。既存の `shouldSaveLocationPoint` が精度、距離、時系列に基づいてGPSログを間引く。OSが実際の更新頻度を調整する点も従来と同じである。

### Appによる記録モード同期

Appは、起動時とフォアグラウンド復帰時に権限状態を再取得した後、記録モードを同期する。

常時記録モードの場合:

1. 登録済みタスクがあれば、Issue #89で追加した処理により古いオプションだけを同名更新する
2. 未開始なら既存の自動開始処理でバックグラウンドタスクを開始する
3. 前景位置監視からは保存しない

フォアグラウンド限定記録モードまたは権限なしの場合:

1. 登録済みバックグラウンドタスクがあれば明示的に停止する
2. フォアグラウンド限定記録モードかつ `AppState === 'active'` の場合だけ前景位置監視を有効にする
3. 権限なしの場合は前景位置監視も無効にする

ここでの `stopLocationUpdatesAsync` は、Issue #89で禁止した「設定更新のためのstop」とは目的が異なる。ユーザーがバックグラウンド記録を許可していない状態へ変わったため、以前の登録を破棄して権限状態と実動作を一致させる処理である。

起動時の順序は、権限確認前に既存タスクの設定を更新しないよう変更する。DBと権限状態を取得した後、権限に応じて「既存タスク更新または停止」を選び、その後に必要なら自動開始する。

現在の `App.tsx` は `updateBackgroundLocationTaskOptionsIfNeeded()` を呼んだ後に `refreshData()` で権限を取得しているため、この呼び出し順序を実装時に明示的に変更する。起動時とフォアグラウンド復帰時は、以下の順序へ統一する。

```text
記録モード同期中にする
  → refreshData()で権限と登録状態を取得する
  → バックグラウンド権限あり:
      updateBackgroundLocationTaskOptionsIfNeeded()
      maybeStartRecordingAutomatically()
  → バックグラウンド権限なし:
      stopBackgroundLocationRecording()
  → 記録モード同期済みにする
```

`updateBackgroundLocationTaskOptionsIfNeeded()` の既存の起動前呼び出しは削除し、バックグラウンド権限がある分岐からだけ呼ぶ。

権限状態がReact stateへ反映されてからバックグラウンドタスク停止が完了するまでの間に前景保存が始まらないよう、Appは「記録モード同期済み」状態を持つ。フォアグラウンド限定保存を有効にする条件は次のとおりとする。

```text
shouldDisplayCustomLocation = !userLocationIcon.useNativeUserLocation
shouldPersistForegroundLocation =
  appState === 'active'
  && isWhileInUseRecordingMode
  && isLocationRecordingModeSynchronized
foregroundWatchEnabled =
  appState === 'active'
  && (shouldDisplayCustomLocation || shouldPersistForegroundLocation)
```

カスタムアイコンの表示だけなら記録モード同期の完了を待たず、従来どおり前景監視を利用できる。フォアグラウンド限定保存は、以前のバックグラウンドタスク停止を含む同期処理が完了してから有効にする。

バックグラウンド権限がない分岐では、タスクが未登録であることを確認できた場合、または登録済みタスクの停止に成功した場合だけ「記録モード同期済み」にする。停止に失敗した場合は同期中のままにして前景保存を開始せず、二重保存の可能性を作らない。エラーを利用者へ表示し、次回の権限再同期時に停止を再試行する。

### 常時記録モードとカスタムアイコンの互換性

常時記録モードかつカスタム現在地アイコンの場合、以下の2つが動作する。これは修正前と同じ構成である。

- 固定名 `strollia-background-location-task` のバックグラウンドタスク1件: GPSログ、Visited Grid、実績を保存する
- `Location.watchPositionAsync` の前景購読1件: カスタム現在地アイコンの表示と追従へ現在地を渡す

`watchPositionAsync` はTaskManagerへタスクを登録せず、コンポーネントのライフサイクルに紐づく購読を返す。したがって、カスタムアイコンの前景購読によって同名タスクや別名タスクが増えることはない。

常時記録モードでは `shouldPersistForegroundLocation` が必ず `false` になるため、前景購読から位置情報保存セッションを呼ばない。保存元はバックグラウンドタスクだけであり、二重保存しない。Issue #89の設定更新も固定名の既存タスクに対する条件付きupsertであり、タスク数を増やさない。

## データフロー

### フォアグラウンド限定記録

```text
AppState active
  → 前景位置監視開始
  → 新しいLocationObjectを受信
  → 画面表示を更新（必要な場合）
  → 保存処理キューへ追加
  → 前景用の位置情報保存セッション
  → Visited Grid更新
  → 保存判定
  → SQLiteへGPSポイント追加
  → 実績処理
```

### 常時記録

```text
Expo background location task
  → LocationObject配列を受信
  → タスク呼び出し用の位置情報保存セッション
  → Visited Grid更新
  → 保存判定
  → SQLiteへGPSポイント追加
  → 実績処理
```

常時記録モードでは、アプリがフォアグラウンドでも保存元はバックグラウンドタスクだけにする。カスタムアイコン用の前景位置監視が動作していても、そこから保存セッションは呼ばない。

## UI表示

設定画面のタイトル「アプリ起動中のみ記録」は維持する。説明文はプロセスが存在するだけで記録されるという誤解を避けるため、以下の意味になるよう更新する。

```text
アプリを画面に表示しているときのみ記録します。
常に記録したいときは設定画面で変更してください。
```

新しいボタン、画面、設定値は追加しない。記録開始・停止は権限状態とAppStateから自動的に決定する。

## エラー処理

- フォアグラウンド権限が取得できない場合は監視を開始せず、既存の権限案内を表示する
- 前景監視の開始に失敗した場合は警告ログを残し、Appのメッセージ表示へ通知する
- 前景位置の保存に失敗した場合はその更新のエラーを記録し、後続の位置更新を処理できるようPromiseチェーンを継続する
- バックグラウンドタスクの停止に失敗した場合は警告とAppのメッセージを表示する。権限再同期時に再試行する
- 実績処理の失敗は既存どおりGPSポイント保存を取り消さず、警告を残して次の処理へ進む
- 購読解除後に新しいコールバックを処理しない

1件の保存失敗によって前景位置監視全体を終了させない。一方、バックグラウンドタスク停止失敗は、表示上のモードと登録状態が一致しないため利用者へ通知する。

## テスト方針

テストの説明文は日本語で記載する。

### 共通位置情報保存セッション

- 複数の位置情報を時系列順に変換・保存する
- セッション開始時に最新保存点をDBから1回だけ取得する
- 1件ずつ位置情報を渡しても、メモリ上の前回点を次の距離・時系列判定へ引き継ぐ
- 同じセッション中は位置更新ごとに最新保存点をDBから再取得しない
- GPSログ保存対象外でもVisited Gridを更新する
- 保存対象だけをSQLiteへ追加する
- 最新保存点を後続位置の判定へ引き継ぐ
- GPSポイント保存後に実績処理を行う
- 実績処理に失敗しても保存済みGPSポイントを維持する
- 保存処理失敗後はセッションを再初期化し、DBの最新点と状態を合わせる

バックグラウンドタスクのテストでは、位置情報配列を共通保存セッションへ渡すことと、空配列・タスクエラー時に呼ばないことを確認する。

### 前景位置監視フック

- 表示も記録も不要な場合は監視を開始しない
- 表示だけの場合は従来のBalanced設定を使う
- 記録する場合はHigh設定を使う
- 最終取得位置は表示へ渡すが保存しない
- 新しい位置更新を表示と保存へ渡す
- 表示と記録が同時に必要でも監視は1つだけ開始する
- 複数の位置更新に対する保存処理を直列実行する
- 無効化・アンマウント時に監視を解除する
- 保存失敗後も次の位置更新を処理する

### App連携

- フォアグラウンド限定記録モードかつ `active` の場合に保存付き前景監視を有効にする
- フォアグラウンド限定記録モードで `inactive` または `background` へ移行すると監視を解除する
- フォアグラウンド復帰時に監視を再開する
- `enabled` に `appState === 'active'` が含まれ、`inactive` への遷移で購読を解除する
- フォアグラウンド復帰時は、バックグラウンドタスクの停止または更新が完了してから前景保存を再開する
- 常時記録モードでは前景監視から保存しない
- OS標準現在地アイコンでもフォアグラウンド限定記録を有効にする
- カスタムアイコンと記録が同時でも前景監視を重複させない
- 常時記録かつカスタムアイコンでは、表示用購読を1件だけ開始し、保存セッションを呼ばない
- バックグラウンド権限がない場合は登録済みバックグラウンドタスクを停止する
- バックグラウンドタスク停止に失敗した場合は前景保存を開始しない
- バックグラウンド権限がある場合だけ登録済みタスクのオプションを更新する
- 起動時に権限取得より前のタスクオプション更新を行わない

### UI

- フォアグラウンド限定記録モードで、画面表示中だけ記録する旨を表示する
- 既存の「設定を開く」導線を維持する

## ドキュメント更新

実装時に `docs/architecture.md` の位置情報記録方針を更新し、以下を明記する。

- 権限状態ごとの保存元
- AppStateが `active` の場合だけ前景限定記録を行うこと
- 前景・背景で保存セッションを共有すること
- 常時記録時は前景監視から二重保存しないこと
- バックグラウンド権限がなくなった場合は登録済みタスクを停止すること

Issue #89の設計書にある「権限仕様を変更しない」という記述は当時のPRスコープを示す履歴として維持する。本修正は別ブランチ・別PRで、その未対応範囲を補完する。

## 実機確認

iOS・Androidで以下を確認する。

1. フォアグラウンド権限だけを付与する
2. OS標準現在地アイコンのまま歩行し、画面表示中にGPSログとVisited Gridが増えることを確認する
3. カスタム現在地アイコンへ変更し、表示・追従と記録が同時に動作することを確認する
4. アプリをバックグラウンドへ移し、その間の位置が保存されないことを確認する
5. フォアグラウンドへ戻し、記録が自動で再開することを確認する
6. 常時許可へ変更し、バックグラウンドでも記録されることを確認する
7. 常時許可からフォアグラウンド権限のみに戻し、登録済みバックグラウンドタスクが停止することを確認する
8. 常時許可中にアプリを前面表示しても、同一位置更新が前景・背景から二重保存されないことを確認する

## 非対象と制約

- DBスキーマと既存ログ形式は変更しない
- GPSポイント、Visited Grid、実績の保存ルールは変更しない
- OSが位置情報更新頻度を調整する挙動は変更できない
- `inactive` または `background` から `active` へ戻るたびに前景位置監視を開始し直すため、iOS・AndroidともにGPSの再取得まで短い遅延が生じる場合がある
- アプリが強制終了された後にフォアグラウンド限定記録を継続しない
- `inactive` または `background` 中に前景限定記録を継続しない
- 手動の記録開始・停止ボタンは追加しない
- 位置情報や写真メタデータを外部へ送信しない
