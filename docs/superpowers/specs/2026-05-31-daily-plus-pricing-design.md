# Daily Plus Report and Pricing Design

## 1. Goal

Strollia Plusの課金対象を、GPS記録そのものではなく「1日の移動をより深く振り返る体験」へ整理する。

基本の日別ログ表示は無料のまま維持し、Plusでは同じ日別体験の中に詳細レポート項目と日別移動リプレイを追加する。これにより、StrolliaをローカルファーストGPSロガーとして成立させつつ、塗りつぶしゲームとしての継続価値をPlusへ寄せる。

## 2. Scope

### In scope

- 月額300円、年額3,300円をStrollia Plusの初期価格方針としてdocsへ記載する
- 日別ログの基本表示は無料機能として明記する
- 日別詳細レポートをPlus機能として定義する
- 日別移動リプレイをPlus機能として維持する
- VisitedCellをユーザー向けには「エリア」と呼ぶ方針を定義する
- 端末移行時のサブスク復元方針をdocsへ記載する
- 天気/気温は初期スコープから外し、将来追加時点以降に保存できる拡張項目として記載する

### Out of scope

- 日別詳細レポート画面の実装
- 天気APIまたはWeatherKitの導入
- 過去日の天気バックフィル
- Sign in with Apple連携
- 独自アカウント機能
- ストア/RevenueCat Dashboardの実設定

## 3. Product Boundary

無料機能は、GPSロガーとして必要な最小体験を担う。

- GPSログの記録
- ローカル保存
- 全履歴マップ表示
- 基本の日別ログ表示
- 基本のエリア塗りつぶし表示
- GPX/KMLインポート/エクスポート

Plus機能は、蓄積した移動ログをより楽しく、深く振り返る体験を担う。

- 日別詳細レポート
- 日別移動リプレイ
- 高度統計
- 月次/年次レポート
- 現在地アイコン変更
- エリア色変更

日別ログそのものをPlusで塞がない。ユーザーが記録した移動を確認できることは、Strolliaの基本価値に含める。

## 4. Daily Detail Report

日別詳細レポートは、日別ログ画面の中で表示項目を増やすPlus機能とする。

初期候補は、端末内SQLiteに保存済みのデータから算出できるものを優先する。

- その日に訪問したエリア数
- その日に新規訪問したエリア数
- その日に解除した実績
- その日の移動距離
- その日の記録時間
- その日の記録点数
- 月次/年次レポートに使う集計の一部

「エリア」は内部実装上のVisitedCellをユーザー向けに言い換えた表現である。Strolliaは移動記録アプリであると同時に、地図を塗りつぶしていくゲーム的な体験を持つため、画面文言や仕様説明では「エリア」を優先する。

内部コードの型名やDB名は、既存実装との整合性を優先してすぐには全面改名しない。ユーザーに見える文言、docs上のプロダクト説明、Plus特典名から段階的に「エリア」へ寄せる。

## 5. Weather Extension

天気、最高気温、最低気温は初期スコープから外す。

理由は、現在のローカルGPSログだけでは算出できず、外部APIまたはOS/プラットフォーム機能との連携が必要になるためである。導入時には、位置情報を天気取得に使うこと、取得タイミング、保存範囲、失敗時の表示、プライバシー説明を追加で設計する。

将来追加する場合は、追加時点以降の日別天気情報をSQLiteに保存する。過去分は自動補完せず、データがない日は「天気データなし」として扱う。過去天気のバックフィルはAPI利用料、取得制限、位置情報送信の説明が必要になるため、別スコープとする。

## 6. Pricing

Strollia Plusの初期価格は以下とする。

- 月額: 300円
- 年額: 3,300円

年額は月額12か月分の3,600円から300円引きで、約8.3%の割引になる。強い年額誘導よりも、ローカルファーストGPSロガーとして無理のない初期価格にする。

商品IDは既存方針を維持する。

- `strollia_plus_monthly`
- `strollia_plus_yearly`

実際の価格表示はRevenueCat Offering / Productから取得したストア表示を優先する。docs上の価格は初期設定方針であり、アプリ内に固定文字列として埋め込まない。

## 7. Restore and Device Migration

現時点ではStrolliaに独自アカウントがないため、RevenueCatの匿名App User IDを使う。

同一ストアアカウントであれば、端末移行後に設定画面の「購入を復元」からサブスクを復元できる想定である。iPhone AからiPhone Bなど同一プラットフォーム内の移行では、App Storeアカウントの購入履歴を `restorePurchases()` でRevenueCatへ送る。

RevenueCat DashboardのRestore Behaviorは、アカウントなしアプリで復元しやすい設定にする。初期方針は `Transfer to new App User ID` とする。

iOSからAndroidのようにストアをまたぐ移行は、匿名App User IDだけでは自動的にはつながらない。将来クロスプラットフォーム復元を扱う場合は、Sign in with AppleなどのログインID連携を別途設計する。

Apple IDそのものはアプリから取得できないため、RevenueCat App User IDには使わない。将来ID連携を行う場合は、Sign in with Appleで返るアプリ/開発チーム単位の識別子を `Purchases.logIn()` に渡す。

## 8. Testing and Verification

この設計PRではコード実装を行わないため、単体テストの追加は不要である。

後続の実装では以下をテストする。

- Plus無効時は日別詳細項目がロックまたはPlus案内になる
- Plus有効時は日別詳細項目が表示される
- 新規訪問エリア数が既存エリアと当日エリアの差分から算出される
- その日に解除した実績だけが日別詳細に表示される
- RevenueCat Offeringの価格表示をアプリ内固定価格より優先する
