# 横画面の2段構成(iPad・iPhone Duo対応 第2弾) 設計書

- 作成日: 2026-11-05
- 前提: PR #196 で iPad 対応(`supportsTablet: true`、iPad は全向き、iPhone は縦のみ)と、地図画面ダッシュボードの横幅上限を導入済み

## 1. 目的と背景

iPad の横向きや iPhone Duo を開いたときの横長表示では、縦1列の画面が横に間延びし、地図とリストを同時に見られない。
地図を持つ画面は「左に項目、右に地図」の2段構成にして、横長画面の広さを活かす。
地図を持たない画面のうち、間延びが目立つ実績一覧と設定の Plus 案内も横長向けに並べ直す。

## 2. ゴール

1. 横画面のとき、日ごとの記録(詳細)とスタンプラリー(パック詳細)を左右50:50の2段構成にする
2. 横画面のとき、実績一覧のアイコンを6列にする
3. 横画面のとき、設定画面の Strollia Plus 案内を左右2列にする
4. 縦画面(iPhone 全般・縦向き iPad)の見た目は一切変えない

## 3. 非ゴール / アンチゴール

- 日ごとの記録の一覧画面(`DailyLogsScreen`)、月次レポート、設定のその他項目、FAQ・ライセンス等は変更しない
- 課金モーダル(`PremiumPaywallModal`)は変更しない(iPad では `pageSheet` が中央の狭いシートになり、2列にする幅がないため。ユーザー確認済みの判断)
- 地図画面(`MapScreen`)は変更しない(前回 PR で対応済み)
- **アンチゴール:** 縦画面のレイアウト・余白・フォントが1pxでも変わること。共有画像(`DailyLogShareCard`)の見た目が変わること

## 4. 横画面の判定

- 判定は `useWindowDimensions()` の `width > height` のとき「横画面」とする(ユーザー確認済み)
  - iPad 横向き、iPhone Duo の内側画面の横長表示、iPad の Split View で横長になった場合が該当する
  - 縦向き iPad、iPhone(縦固定)は該当しない
- 判定は純粋関数(例: `isLandscapeLayout(width, height): boolean`)として切り出し、単体テストする。不正値(NaN・0以下)は縦扱い(false)にする
- 画面回転・ウィンドウサイズ変更時は `useWindowDimensions()` の再レンダーで即座に切り替わる。状態の保持(スクロール位置など)は求めない
  - 縦横の切り替えで地図(`MapView`)が作り直され、表示範囲やスポットへのズームは初期状態に戻る。これは許容する(設計者判断)

## 5. 共通部品: 2段レイアウト

- 汎用コンポーネント `TwoPaneLayout`(仮称、1ファイル1コンポーネント)を `src/ui/components/` に新設する
  - props: `isTwoPane: boolean`、`primary`(左側=項目)、`secondary`(右側=地図)、`styles`
  - `isTwoPane` が false のときは、呼び出し側の既存の縦レイアウトをそのまま描画できるよう、このコンポーネントを使わない分岐にしてもよい(縦画面の見た目を変えないことを最優先する。どちらにするかは実装者の判断)
  - 2段時は `flexDirection: 'row'`、左右とも `flex: 1`(50:50、ユーザー確認済み)
- スタイルは `src/ui/styles/` の該当ファイル(共通なら `commonStyles.ts`)に追加し、`StyleSheet.create` をコンポーネント内に書かない(ESLint で強制)
- 左右の間に区切り線や余白を入れるかは、`DESIGN.md` のトークンに合わせて実装者が決める(カードを多用しない方針は守る)

## 6. 画面ごとの仕様

### 6.1 日ごとの記録(詳細) `DailyLogDetailScreen`

現状: `ScrollView` 内に「`routeTimeline`(`RouteMapPanel` + `StepSlider` + GIF出力ボタン)」→ `DailyLogShareSections` → おもいで(Plus未加入時のブラー) → アクション群(共有・Plus導線)の順。

横画面時:

- **右側(固定、スクロールしない):** `RouteMapPanel` + `StepSlider`(シークバー) + 「移動記録をGIFで出力」ボタン。地図は右側の高さいっぱいに広げ、シークバーとGIFボタンはその下に置く
- **左側(スクロール):** `DailyLogShareSections` → おもいで → アクション群
- ヘッダー(`AppScreenHeader`)は左右をまたいで画面上部に置く(現状どおり)
- シークバー操作中に左側のスクロールを止める現在の挙動(`isSliderDragging`)は、2段時は不要になるが、残しても害はない
- 画面外の共有用カード(`DailyLogShareCard`)・GIF生成用レンダラー・各ダイアログは変更しない
- `RouteMapPanel` の地図枠(`routeMapFrame`)は高さ332固定で、GIF範囲選択ダイアログとも共用している。右ペインで高さいっぱいに広げるため、上書き用のスタイル指定を追加する。ダイアログ側の見た目は変えない(設計者判断)
- ルートがない日や Plus 未加入でシークバー・GIFボタンが出ない日も、横画面なら2段構成のまま表示する(設計者判断)

### 6.2 スタンプラリー(パック詳細) `LandmarkPackScreen`

現状: `landmarkPackScreenBody` 内で地図(`flex: 1`)が上、スポット一覧の `ScrollView`(`flex: 2`)が下。

横画面時:

- **左側(スクロール):** スポット一覧
- **右側(固定):** `LandmarkPackMapPreview`
- 行タップの挙動(到達済み→日別記録詳細、未到達→埋め込み地図のズーム)は変えない

### 6.3 実績一覧 `AchievementListScreen`

- 横画面時、実績アイコンのグリッドを3列から6列にする
- 現状はタイル幅を `(windowWidth - 24*2 - 10*2) / 3` で計算し、`achievementGridTile` の `flexBasis: '30%'` で並べている。列数を引数に取る純粋関数(例: タイル幅・画像サイズ計算)に切り出し、3列/6列の両方をテストする
- スポットパック一覧(リスト行)は変更しない

### 6.4 設定画面の Strollia Plus 案内 `SettingsScreen`

対象: Plus 未加入時に表示される `settingsSubscriptionActions` ブロック。

横画面時:

- **左列:** 上に案内文(`InfoBlock`「Strollia Plus(有料サブスクリプション)のごあんない」)、その下に「いつでも解約できます。」、月額/年額で始めるボタン・購入を復元ボタン・商品情報読み込み中の文言を **下揃え** で配置する(左列の高さは右の画像に合わせ、ボタン群が左列の下端に寄る)
- **右列:** 宣伝画像(`PlusAdImage`)
- **2列の下(全幅):** 規約・プライバシーポリシーのリンク(`paywallLegal`)。ユーザー確認済み
- 左右比は 50:50 とする(実装者判断で調整可。画像が大きすぎて画面に収まらない場合は右列を狭めてよい)

## 7. テスト方針

- 横画面判定の純粋関数: 横長・縦長・正方形(縦扱い)・不正値
- 実績グリッドのサイズ計算関数: 3列・6列
- 各画面のコンポーネントテスト: `useWindowDimensions` をモックし、横画面では左右のペイン(testID など)に期待する要素が入ること、縦画面では従来どおりの構造であることを確認する
  - 既存テスト(`DailyLogDetailScreen.test.tsx`、`AchievementListScreen*.test.tsx`、`LandmarkPackScreen` のテスト、`SettingsScreen` のテスト)が縦画面のまま全て通ること
