# MVP仕様

## 1. 目的

MVPでは、Strollia の核となる「GPSログを記録し、ローカルに保存し、日別にマップで見返し、GPXとして取り出す」体験を完成させる。

## 2. MVPの範囲

MVPで提供する機能は以下とする。

- 位置情報権限許可後の自動GPS記録
- 初回起動時のチュートリアルダイアログ
- 自動開始後のバックグラウンドGPS記録
- SQLiteへのローカル保存
- 日別ログ一覧
- 日別マップ表示
- GPXエクスポート
- GPXインポート
- OS設定に追従するダークモード
- フォアグラウンド時の画面ON維持設定

## 3. 記録方式

初期実装では、位置情報権限が揃ったらGPS記録を自動で開始する。通常時の記録開始・停止操作は表示せず、自動開始に失敗した場合のみ設定画面に復旧用の「記録開始」ボタンを表示する。自動開始後は、アプリがバックグラウンドに移動してもGPSログ保存を継続することを目指す。

初回起動時は、共通ダイアログでアプリ概要、画面下の主要項目、実績システム、安全に歩くための注意事項、位置情報権限の開始導線を順番に案内する。権限要求はチュートリアル内では実行せず、チュートリアルを閉じたあとに地図上の位置情報案内パネルから続けられることを伝える。完了後も設定画面の「チュートリアル」から同じ内容を再表示できる。

理由は以下である。

- 権限許可を記録開始の意思として扱える
- インストール後に設定画面で開始ボタンを探す手間をなくせる
- 自動開始失敗時だけ復旧操作を出すことで通常操作を単純にできる
- GPSログ保存とマップ表示という中核機能に集中できる

## 4. 画面構成

MVPの画面は以下を想定する。

- メインマップ画面
- 日別ログ画面
- 設定画面

メインマップ画面は地図を全面表示し、記録状態と右上メニューを地図上に重ねて表示する。基本表示は全期間のGPSログとし、日別表示は右上メニューから開く別画面で扱う。開始地点・終了地点のピンはメインマップには表示しない。設定画面では記録状態、権限導線、自動開始失敗時の復旧用開始ボタン、データのエクスポート/インポートを扱う。

## 5. 成功条件

MVP完了条件は以下とする。

- アプリを起動できる
- 初回起動時にチュートリアルを確認でき、次回起動以降は再表示されない
- 位置情報権限を許可できる
- 権限許可後、GPSポイントがSQLiteに自動保存される
- 自動開始に失敗した場合は設定画面から記録開始を再試行できる
- 保存済みの日別ログを確認できる
- 選択日のルートがマップ上に線で表示される
- 選択日のログをGPXとして共有できる
- GPXファイルを選択し、既存データを優先しながら取り込める

## 6. MVPの非対象

以下はMVPには含めない。

- ユーザー操作による任意の一時停止
- from-to のA/B点範囲指定
- KML対応
- KMLインポート
- 写真ジオタグ表示
- 全履歴マップの高度な描画最適化

## 7. 技術候補

- アプリ: Expo + React Native + TypeScript
- 位置情報: `expo-location`
- DB: `expo-sqlite`
- マップ: `react-native-maps`
- ファイル出力: `expo-file-system`
- 共有: `expo-sharing`
