# マップ表示仕様

## 1. 基本方針

Strollia では、保存したGPSログをマップ上にプロットし、位置情報ポイントを線でつないで移動ルートとして表示する。

表示対象は以下とする。

- 1日単位の移動ルート
- from-to で指定した任意範囲の移動ルート
- これまでの全記録を重ねた全履歴マップ
- 任意機能として、ジオタグ付き写真を重ねたマップ

## 2. マップライブラリ方針

初期候補は `react-native-maps` とする。

理由は以下である。

- Expoで利用しやすい
- iOS / Android の両方に対応している
- iOSではApple Maps、AndroidではGoogle Mapsを利用できる
- `Polyline` によりGPSログを線として描画しやすい

## 3. 地図プロバイダー方針

### 3.1 第一候補

初期実装では、OS標準に近い地図表示を第一候補とする。

- iOS: Apple Maps
- Android: Google Maps

この構成はユーザーに馴染みがあり、React Native / Expoで扱いやすい。

### 3.2 OpenStreetMapの扱い

OpenStreetMapは地図データ自体は自由に利用できるが、OpenStreetMap Foundation の標準タイルサーバーは容量に限りがあり、利用ポリシーを守る必要がある。

そのため、初期仕様では OpenStreetMap 標準タイルサーバーの直接利用を本番アプリの前提にはしない。

OpenStreetMapを利用する場合は、以下のいずれかを検討する。

- 利用規約に合うOSM系タイルプロバイダーを利用する
- 必要な範囲のタイルをユーザー操作でキャッシュまたは保存する
- 将来的に自前タイルサーバーを用意する
- オフライン地図対応が必要になった段階で別ライブラリを検討する

ただし、自前タイルサーバーは運用費が発生するため、初期方針とは相性が悪い。

## 4. 描画仕様

### 4.1 GPSポイント表示

GPSログの各点は、必要に応じてマップ上にプロットできる。

ただし、常に全点をマーカー表示すると視認性とパフォーマンスが悪くなるため、メインマップでは visited grid overlay を中心とする。

メインマップでは開始地点・最新地点のマーカーは表示しない。全履歴を俯瞰するときの視認性を優先する。

### 4.2 Visited Grid Overlay

メインマップでは、Polylineを主表示にせず、GPS点が存在した100mセルを visited cell として表示する。

visited cell は SQLite の `visited_cells` に保存し、MapView上ではPolygonとして描画する。ズームアウト時は100mセルを200m、500m、1km、2km、5km、10km相当の表示セルへ集約する。集約時は、大セル内にvisitedな100mセルが1つでもあれば大セル全体をvisitedとして扱う。

表示セルサイズは `latitudeDelta` が大きくなるほど段階的に上げる。100mセルは `latitudeDelta < 0.06` まで維持し、少し広域にした程度では200m以上へ切り替えない。

表示セルサイズの切替境界ではヒステリシスをかける。直前の表示セルサイズを保持し、境界付近でズーム値が小さく揺れた場合に100m/200mなどが短時間で入れ替わらないようにする。結合されない表示セルはセルIDをそのままPolygonの安定IDとして使う。Polygon結合(後述)は整列ブロック単位でのみ行うため、結合後セルも `結合後セルサイズ:x:y` という一意なIDを持ち、スクロールしてもブロック境界とReact keyが動かない。

表示範囲内のvisited cell取得では、端セルの出入りによるちらつきを抑えるため、表示範囲の外側にも設定値ぶんの余白を持たせて先読みする。定期的なGPSログ再読み込み時には、`location_points` の件数変化がなくてもvisited cellを再取得し、Visited Gridの表示をSQLiteの `visited_cells` と同期する。

Grid取得用の表示範囲は、地図カメラ用の表示範囲(`visibleRegion`)とは別に `gridSyncRegion` として保持する。ユーザーが地図をドラッグしている間(`onPanDrag` 以降)はこの範囲を更新せず、DB取得と大量Polygon更新をジェスチャー中に走らせない。ドラッグ終了は `onRegionChangeComplete` でまとめて検知し、そこで `gridSyncRegion` を追従させる。`onRegionChangeComplete` が届かないケースに備え、最後の操作イベントから1000ms経過したら直近の表示範囲へ同期するアイドルタイマーをフォールバックとして持つ(タイマーは操作イベントのたびに張り直す)。現在地追従の自動センタリング、現在地ボタン、地図復帰など、ユーザー操作を経由しないプログラムによる移動はこの抑止の対象にせず、従来どおり即時に同期する。

visited cellのうち、GPS記録によって新しく開いたセル(fresh cell)だけが0.5秒でフェードインする。スクロールや定期再取得によって表示範囲に入っただけの既存セル(stable cell)はフェードさせず即時表示する。fresh判定は100m基本セルID(`100:x:y`)単位で保持するため、表示セルサイズがズームで変わってもfresh扱いは失われない。検出は「前回取得・今回取得がともに100m表示だったとき」に限り、「前回取得済みの範囲に完全に含まれるのに前回は返ってこなかったセル」をfreshとする。fresh cellがstableへ戻る(=フェード対象・結合除外から外れる)条件は表示範囲外に出たときだけで、判定には先読み余白を含まない実表示範囲を使い、DB再取得を伴わない表示範囲変更でも実行する。1回の検出で64件を超えた場合はフェードを行わない(結合対象からの除外は維持する)。`visited_cells` には `first_visited_at`、`last_visited_at`、`visit_count` を保持しているため、将来のレポートでは初回訪問日時、再訪日時、訪問回数を集計できる。

表示セルは1セル1Polygonとして描画し、セル同士の境界線は描画しない。ただし、グリッド整列した正方形ブロック(`4x4` / `2x2`)が完全に埋まっている場合だけ、1つの大きいPolygonへ結合する。ブロック内に未訪問セルが1つでもあれば結合せず、より小さいブロックか単体セルへ落とすため、未訪問エリアを塗ることはなく100m四方の表示意味は保たれる。この結合は全ズーム段階(100m表示・200m以上の集約表示)で行う。100m表示ではfresh cellを結合対象から除外する。200m以上ではfreshを考慮せず、表示されている全セルをstableとして結合する。集約表示は「表示セル内にvisitedな100mセルが1つでもあれば表示セル全体を塗る」仕様のため、完全に揃った`2x2`/`4x4`をまとめても塗り範囲は変わらない。任意長方形の結合と`8x8`以上のブロックはズーム段階によらず行わない。visited cell色はテーマのprimaryを既定値とし、`GRID_OVERLAY_CONFIG` の設定値で差し替えられるようにする。

現在地追従中は現在地更新のたびにvisited cellを再取得するが、取得できた表示セルIDの集合が前回と同じで、かつ新しく開いたセル(fresh cell)がない場合は描画データを更新しない。Polygon結合・座標変換・Polygon生成を丸ごと省くことで、同じ場所を歩き続けている間の定常負荷を下げる。同一性の比較にはセルIDだけを使い、`visit_count` や `last_visited_at` は見ない。現在地セルのこれらの値はGPS記録のたびに更新されるため比較へ含めると更新スキップが成立しなくなるうえ、描画はセルIDと座標・テーマ色だけで決まるため表示にも影響しない。再取得そのものは従来どおり行うため、新しいセルが開いたときの表示遅延は増えない。あわせてメインマップ側でもPolygon要素の配列をメモ化し、描画データが変わらない限りPolygonの再構築が起きないようにする。

Fog opacity は `latitudeDelta` に応じて線形補間し、通常表示では薄く、広域表示では濃くする。opacityやセルサイズ候補は `GRID_OVERLAY_CONFIG` に集約し、実機調整しやすくする。

低速移動ではGPS点が存在したセルのみを開放し、点間補間はしない。150km/h以上の高速移動では、GPS点が飛び飛びになりやすいため、visited cell補完専用に点間を補間する。

### 4.3 ルート線表示

軽量保存判定を通ったGPSポイントは、GPX/KMLエクスポート、日別ログ、月次レポート、将来Replay、デバッグ用途として保持する。メインマップではGrid Overlayを主表示とし、Polylineは描画しない。

保存前判定で落としきれなかった境界ケースや過去データに備え、描画時の `RouteSegment` 分割は保険として残す。

日別ログやレポートなど、特定期間のルート確認では必要に応じてPolylineを使う。全履歴メインマップでは、誤線を避けるためvisited cellの蓄積表現を優先する。

### 4.4 記録途切れ区間

GPS取得が長時間途切れた場合、単純に線でつなぐと実際には移動していない経路が描かれる可能性がある。

そのため、以下の条件に該当する場合は線を分割することを検討する。

- 前後の記録点の時間差が一定以上ある
- 前後の距離が不自然に大きい
- 位置精度が低い点が連続している

閾値は詳細仕様で決定する。

### 4.5 メインマップ下部メーター

メインマップ下部には、速度リング、距離情報、画面遷移ボタンをまとめたダッシュボードを置く。

- 左側の速度リングにGPSが返すraw speedを `km/h` へ変換して表示する
- 速度リングは12時方向を0km/hとする連続円弧で描画し、低速は30km/h、車相当は150km/h、高速移動は400km/hで完全円にする。400km/h以上は完全円のまま表示する
- 速度リングはログ保存判定から分離し、保存点の更新頻度に左右されず現在の動きへ即応できるようにする
- 速度帯は low-speed が `30 km/h` 未満、車相当が `30 km/h` 以上 `150 km/h` 未満、高速移動が `150 km/h` 以上とする
- 停止状態はテーマカラーを明るくした色、歩行は緑寄りの青、車相当はオレンジ、高速移動はピンクを使う
- 速度リングと情報帯は半透明背景をSVGの単一パスで成形し、接合部だけ背景色が濃くならない一体形状にする
- 情報帯には通算距離 `ODO`、今日の移動距離 `TODAY`、現在地の市区町村と副地域名を並べる
- 情報帯は `ODO` が100万km整数部 + 小数点以下2桁、`TODAY` が4桁整数部 + 小数点以下2桁を表示できる幅配分にする
- 距離値は整数部の桁数が変わっても右端が動かない右寄せ表示とし、市区町村名は最大6文字程度を表示できる地名領域を確保する
- 下段には `日ごとの記録`、`実績`、`レポートを見る`、`設定`、`マップの表示` のボタンを置く
- `マップの表示` では標準マップと航空写真を切り替え、マップ上の写真表示設定も切り替えられる
- 数値部分はDSEG系フォントを使い、地図上でも一目で読めるようにする
- 距離の小数点以下2桁は数字部分のみ整数部より小さくし、小数点は整数部と同じ大きさで下揃え表示する
- パネルとボタンは `#333333` の80%背景と影を持つ要素として扱う
- 現在地ボタンはダッシュボード上部に置き、現在地アイコンは常に白で表示する

### 4.6 メインマップ上部オーバーレイ

現在地名とマップ操作導線は下部ダッシュボードへ集約する。

- メインマップ上部には固定の市区町村パネル、移動モードパネル、メニューボタンを置かない
- 上部は地図表示を優先し、OSステータスバー、コンパス、開発フラグバナーなど必要な表示だけを残す

## 5. 日単位マップ

日付を選択すると、その日の 0時〜24時 のGPSログを表示する。

表示内容は以下とする。

- 対象日のルート線
- 開始地点マーカー（緑、`開始` ラベル）
- 最新地点マーカー（赤系、`最新` ラベル）
- 記録開始時刻
- 記録終了時刻
- 推定移動距離
- 記録点数

## 6. 範囲指定マップ

from-to で指定した範囲のGPSログを表示する。

範囲指定UIと連動し、A点・B点を動かすたびに、対象範囲のルートをマップ上でプレビューできることを目指す。

## 7. 全履歴マップ

全履歴マップでは、これまで保存されたすべてのGPSログをマップ上に描画する。

目的は、ユーザーがこれまで歩いた場所・移動した場所を俯瞰できるようにすることである。

想定する表示方法は以下である。

- 全期間のルート表示
- 日付、月、年などによる色分け
- 期間フィルター
- 記録密度の高い場所の視覚化
- 大量データ時の間引き表示

## 8. 写真ジオタグ表示（任意機能）

ユーザーが写真ライブラリへのアクセスを許可し、写真表示を有効にした場合、ジオタグ付き写真をマップ上に表示する。

表示はオン/オフ可能とする。

表示方法は以下とする。

- 写真のGPS座標にマーカーを表示する
- マーカーは小さい四角い吹き出しとして表示し、その中にサムネイルを表示する
- 近接する複数写真は1つの吹き出しにまとめ、右下に `+n` の件数バッジを表示する
- 単体写真のマーカーをタップすると、写真を全画面プレビューで表示する
- 複数写真の吹き出しをタップすると、吹き出し内に写真グリッドを表示する
- グリッド内の写真をタップすると、写真を全画面プレビューで表示する。10枚以上ある場合は9枚単位のページとして横スワイプで閲覧する
- 表示中の日付またはfrom-to範囲に撮影された写真のみ表示できるようにすることは将来検討とする
- ジオタグがない写真は表示しない

初期実装では、設定画面で写真表示をONにした場合のみ全履歴マップに表示する。

## 9. パフォーマンス方針

GPSログは長期間蓄積されるため、マップ描画の負荷を抑える必要がある。

初期方針は以下とする。

- 表示範囲に必要なデータだけSQLiteから取得する
- 期間指定時は `recorded_at` で範囲検索する
- 日別表示時は `local_date` で取得する
- 全履歴表示では点数が多い場合に間引きを行う
- ズームレベルに応じて描画点数を調整する
- 写真マーカーは表示範囲に応じた距離判定で近接写真をクラスタリングし、拡大率に応じてクラスタ範囲を上下させる
- 生ログとは別に描画用ルート座標を生成する
- 描画用ルートはDouglas-Peucker法で形状を保ちながら簡略化する
- メインマップでは表示範囲内のvisited cellを取得し、ズームに応じて集約して描画する
- 200m以上の表示セルではSQLite側で `GROUP BY` によるブロック集約を行い、JS側へ渡る行数を抑える。100m表示では従来どおり100mセル行をそのまま返す
- グリッド整列した正方形ブロック(`4x4` / `2x2`)が完全に埋まっている場合だけ、全ズーム段階でPolygonを結合し、描画Polygon数を削減する。100m表示ではfresh cellを結合対象から除外し、200m以上ではfreshを考慮せず全表示セルを結合する
- `EXPO_PUBLIC_LOG_VISITED_GRID_METRICS` を有効にすると、開発時のみセル数・Polygon数・削減率・処理時間をログ出力する。座標・cellId・移動履歴は出力しない
- 取得した表示セルIDの集合が前回と同一でfresh cellもない場合は、描画データの更新自体を省く。現在地追従中の大半の再取得がこれに該当する
- `EXPO_PUBLIC_LOG_VISITED_GRID_METRICS` 有効時は、取得のたびに更新したかスキップしたかを `source=updated` / `source=skipped` として累計付きで出力する。描画データが変わらない回はセル数・Polygon数のログが出ないため、スキップの発生はこちらで確認する

### 9.1 初期表示範囲の計算最適化

メインマップの初期表示範囲は、`getLocationPointsBounds()`で取得した緯度経度の最小値・最大値をもとに `createRegionFromBounds()` 関数で算出する。従来は `createInitialRegion(points)` で全ポイント配列のスプレッド展開(`Math.min(...largeArray)`)を行っていたが、記録ポイント数が100万を超える端末ではスプレッド展開が `RangeError` を起こす問題が発生していた。最適化後は、`createInitialRegion()` 内部のスプレッド展開をシンプルなループ集計に変更し、データ量に依存せず安定して動作するように改善した。`createRegionFromBounds()` では `{minLatitude, maxLatitude, minLongitude, maxLongitude}` オブジェクトから `Region` オブジェクトへ変換する。1.4倍の表示余裕と最小デルタ(0.01)の処理ロジックは従来と同じ。

表示範囲のデルタには有効上限のクランプを設けている。個々の座標は緯度 -90〜90・経度 -180〜180 にバリデーション済みで、外接ボックスの生スパンは最大でも緯度180度・経度360度に収まる。しかしこれに1.4倍の表示マージンを掛けた表示デルタは上限を超えうる(例: 経度スパン269度 → 269×1.4=376.6度)。MapKitは緯度デルタ180度・経度デルタ360度を超える `Region` を `NSInvalidArgumentException`(Invalid Region)にしてクラッシュするため、マージン適用後の `latitudeDelta` を179度未満・`longitudeDelta` を359度未満へクランプする。

## 10. 無料利用についての考え方

地図表示は「アプリ側のサーバー費用を発生させない」ことを重視する。

ただし、地図SDKやタイルプロバイダーには、それぞれ利用規約、APIキー、無料枠、制限がある。

初期判断としては以下とする。

- iOSではApple Mapsを優先する
- AndroidではGoogle Mapsを優先する
- OpenStreetMapは候補として残すが、標準タイルサーバーの本番利用は慎重に扱う
- 商用公開やユーザー増加を想定する段階で、地図プロバイダーの料金・利用規約を再確認する

## 12. 現在地追従

メインマップでは、アプリ起動時の初期状態として現在地追従を有効にする。ユーザーが地図をドラッグして現在地中心から離れると追従はOFFになり、再度有効にするには現在地ボタンを押す必要がある。

ユーザーが地図をスワイプして現在地中心から離れた場合、現在地ボタンを表示する。表示・非表示は0.5秒のフェードアニメーションとする。

地図中心が現在地付近に戻っただけでは追従を再開しない。広域表示や任意地点の確認中に、現在地更新で意図せず表示範囲が引き戻されることを避けるためである。

別画面からメインマップへ戻る場合、現在地追従中かつ現在地が取得済みであれば、MapViewの再マウント時に全履歴の広域 `initialRegion` へ戻さず、現在地中心の通常縮尺へ復元する。このときアプリ側の表示範囲状態も同じRegionへ更新し、Visited Gridの取得範囲と実際の地図表示を同期する。

現在地ボタンには `@expo/vector-icons` の `AntDesign/aim` を使用する。

## 13. 地図UIオーバーレイ

メインマップ操作は下部ダッシュボードへ集約する。日別ログ、実績、レポート、設定は下段ボタンから開き、地図種別と写真表示は `マップの表示` パネルから切り替える。

画面切り替え、地図種別切り替えなどの主要操作では、短いアニメーションと軽いタプティックフィードバックを入れる。

Apple Maps の法的表示やiOS標準コンパスがアプリのオーバーレイに隠れないよう、`mapPadding` と `legalLabelInsets` を設定して安全な余白を確保する。

## 14. 描画軽量化

GPSログの保存用データと描画用データは分けて扱う。保存用データはSQLiteに保持し、メインマップではvisited cellを表示セルサイズへ集約して描画する。日別ログやレポートなどPolylineが必要な画面では、必要に応じてDouglas-Peucker法で簡略化した描画用座標を使う。

メインマップでは `gridSyncRegion`(詳細は4.2)が指す表示範囲に含まれる `visited_cells` だけを取得する。表示セルサイズが基本セルサイズ(100m)より大きい場合はSQL側の `GROUP BY` でブロック集約してから返すため、JS側へ渡る行数自体を削減できる。さらに、グリッド整列した正方形ブロックが完全に埋まっている場合は全ズーム段階で1つの大きいPolygonへ結合する(4.2参照)。広域表示ではセルサイズ自体を大きくすることで、全履歴表示でズームアウト・パンした場合の描画負荷を抑える。

## 15. 日別移動リプレイ

日別移動リプレイでは、選択した1日のGPSログを時系列で再生する。

初期MVPでは、日別ログ画面からリプレイ画面へ遷移し、シークバーで指定した時刻までのルート線を描画する。

表示内容は以下とする。

- 対象日の最初のGPSポイントから、シークバーで指定した時刻までのルート線
- 指定時刻時点の現在位置マーカー
- 現在のリプレイ時刻
- 再生/一時停止ボタン
- シークバー

該当時刻がGPSポイントの間にある場合、初期MVPでは直前のGPSポイントを現在位置として扱う。線形補間は将来改善とする。

初期表示時は対象日のルート全体が入るよう地図をフィットする。自動再生中の地図追従は必須にせず、ユーザーがパン/ズームしてもリプレイ自体は継続する。

この機能は Strollia Plus 候補とし、Plus無効時はリプレイ画面への遷移前にPlus案内を表示する。
