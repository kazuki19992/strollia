# 滞在場所設定（GPS吸着補正・共有時プライバシー範囲）設計

GitHub Issue [#74](https://github.com/kazuki19992/strollia/issues/74) を対象とする。

## 目的

自宅・職場など、長時間滞在する場所をユーザーが登録できるようにする。リアルタイム記録では、その場所の周辺で生じるGPSの揺れを中心座標へ吸着して、距離・地図ルート・エリア（Visited Grid）を安定させる。同時に、共有用の画像・GIF・月次レポートでは、場所ごとに設定した半径内の軌跡を描画しない。

GPSの生座標を失わず、滞在場所の編集・削除やPlusの契約状態によって過去ログの意味が変わらないことを最優先にする。

## 成功条件

- ユーザーは名称、中心座標、共有時の非表示半径を持つ滞在場所を登録、編集、削除、並べ替えできる
- 無料版およびPlus解約中は、一覧先頭の1件だけが有効になる。Plus契約中は全件が有効になる
- 無効な滞在場所もSQLiteに保持し、再契約時には保存済みの全設定が自動で有効へ復帰する
- リアルタイムの端末GPS記録だけが、半径50m・連続3点の条件で滞在場所中心へ吸着する
- 補正後座標を距離、エリア、通常のルート表示に使い、生座標は常に保持する
- アプリ再起動時は未吸着から再判定し、過去ログを再計算しない
- GPXインポートには吸着を適用せず、GPXエクスポートは生座標を出力する
- 有効な滞在場所の非表示半径に入る共有ルートは除外され、除外区間の前後を線で結ばない
- 既存ログは、補正後座標が未保存なら生座標を使い、データ移行時に全件更新しない

## 用語

- **生座標**: OSから受信した `latitude` / `longitude`。改変せず保存する。
- **有効座標**: 記録時に決まった補正後座標。吸着していない場合は生座標と同じ値である。
- **有効な滞在場所**: 現在のPlus契約状態と一覧順から、吸着・共有時の非表示範囲の対象となる滞在場所。
- **吸着中**: 有効座標として滞在場所中心を採用しているランタイム状態。
- **非表示半径**: 共有用成果物において、中心から指定距離以内の点を描画しない半径。`含める` は半径なしを意味する。

## 検討した方式

### 採用: 生座標と有効座標を分けて記録時に保存する

`location_points` の既存の `latitude` / `longitude` は生座標として残す。リアルタイム記録時に決定した有効座標を新しい任意カラムへ保存し、距離、エリア、地図の各利用側は「有効座標があればそれ、なければ生座標」を使う。

この方式では、後から滞在場所を編集・削除しても、保存済みログの距離や軌跡は変わらない。GPXの生データも完全に維持できる。

### 不採用: 生座標を中心座標で上書きする

保存するGPS座標を直接中心座標へ置き換える方法は、GPXエクスポートで元の記録を出せず、将来の判定・調査にも使えないため採用しない。

### 不採用: 表示・集計時に現行設定から補正を再計算する

設定の編集・削除、並び替え、Plusの解約によって過去の距離・ルート・エリアが変化する。また、Issue #74の「過去ログを再計算しない」と矛盾するため採用しない。

## 課金と有効化

滞在場所レコードは契約状態によらず保持する。契約状態から有効なレコードを都度導出し、有効・無効をDBへ書き戻さない。

| 契約状態 | 登録可能件数 | 有効な滞在場所 |
| --- | --- | --- |
| 無料版 | 1件まで | 一覧先頭の1件 |
| Plus | 制限なし | 全件 |
| Plus解約中（保存済み複数件あり） | 新規追加不可 | 一覧先頭の1件 |

一覧は `sort_order` 昇順で表示する。同順位は `id` 昇順で安定させる。並べ替えは無料版・解約中にも許可し、先頭へ移動した場所を有効な1件として選択できる。解約は既存レコードを削除・変更しない。再契約により全件が有効へ戻る。

この有効化規則は、GPS吸着と共有時の非表示範囲に共通で適用する。Plus限定の可否は、既存のRevenueCat entitlementの真偽をアプリ状態から受け取り、純粋関数 `resolveActiveStayPlaces` で判定する。DBの内容だけから有効性を判断してはいけない。

## データモデルと移行

### `stay_places` テーブル

新規テーブルとして、次の列を持つ。

| 列 | 型 | 説明 |
| --- | --- | --- |
| `id` | INTEGER PRIMARY KEY | 滞在場所ID |
| `name` | TEXT NOT NULL | ユーザーが入力する表示名 |
| `latitude` | REAL NOT NULL | 固定中心マーカーの緯度 |
| `longitude` | REAL NOT NULL | 固定中心マーカーの経度 |
| `privacy_radius_meters` | INTEGER NULL | `NULL` は「含める」、それ以外は許可済み半径 |
| `sort_order` | INTEGER NOT NULL | 並べ替え順 |
| `created_at` | TEXT NOT NULL | ISO 8601作成日時 |
| `updated_at` | TEXT NOT NULL | ISO 8601更新日時 |

`privacy_radius_meters` に保存できる値は `100`, `200`, `500`, `1000`, `2000`, `3000`, `5000`, `10000` のみとする。UIの選択肢は `含める`, `100m`, `200m`, `500m`, `1km`, `2km`, `3km`, `5km`, `10km` とする。

`sort_order` を取得するインデックスを追加する。リポジトリ操作は `stayPlaceRepository.ts` に集約し、登録・更新・削除・並べ替えを排他トランザクションで行う。並べ替え時は、一覧の全レコードに連番を再設定する。

### `location_points` の追加列

既存の生座標を変更せず、次の任意列を追加する。

| 列 | 型 | 説明 |
| --- | --- | --- |
| `effective_latitude` | REAL NULL | 記録時に決定した有効緯度 |
| `effective_longitude` | REAL NULL | 記録時に決定した有効経度 |
| `snapped_stay_place_id` | INTEGER NULL | 吸着した滞在場所ID。非吸着ならNULL |

追加列を持たない既存行は更新しない。座標を読む共通変換関数 `toEffectiveLocationPoint` は、両方の有効座標が存在する行だけを使い、片方だけ・不正値の場合は生座標へフォールバックする。過去行へ有効座標を補完するバッチ処理は実装しない。

DB初期化は既存の段階的migration方式で新しいテーブル・列・インデックスを追加する。`CREATE TABLE IF NOT EXISTS` だけで既存DBの列追加を済ませず、既存の `ensureColumn` を使って必要な列を追加する。外部キーを利用しても滞在場所削除時にログの `snapped_stay_place_id` を失わせないため、当該列は履歴参照用の任意IDとして扱い、削除時は `ON DELETE SET NULL` を使う。座標そのものは保存済みのため、IDがNULLになっても履歴の有効座標は変わらない。

## GPS吸着

### 対象と非対象

吸着は `locationRecordingSession` で受け取るリアルタイムの端末GPSだけに適用する。次の経路には適用しない。

- GPXインポート
- 既存ログの表示・再計算
- GPXエクスポート
- 端末現在地アイコンの表示

吸着判定が必要なリポジトリ、UI、Expo APIを直接参照しないよう、`stayPlaceSnapResolver.ts` を純粋関数として分離する。

### 状態と判定規則

ランタイム状態は `activeStayPlaceId`、入場候補IDと連続数、退出連続数を持つ。これは位置情報保存セッションだけが保持し、SQLiteへ保存しない。セッション開始・アプリ再起動時は、すべて未吸着・連続数0から始める。

| 状態 | 現在の生座標 | 判定 | 出力する有効座標 |
| --- | --- | --- | --- |
| 未吸着 | 有効な場所の半径50m内 | 同じ候補が3連続で確認されるまで候補を継続 | 生座標 |
| 未吸着 | 半径外 | 入場候補をリセット | 生座標 |
| 吸着中 | 吸着先の半径50m内 | 退出連続数をリセット | 吸着先中心 |
| 吸着中 | 吸着先の半径50m外 | 3連続で外になるまで吸着を維持 | 吸着先中心 |
| 吸着中 | 3連続で半径外 | 吸着を解除し、退出を確認した現在点から未吸着へ戻る | 生座標 |

境界は「中心から50m以下」を範囲内とする。複数の有効な場所の半径に同時に入った場合は、中心までの距離が最小の場所を候補にする。同距離なら `sort_order`、`id` の順で決定する。

入場が3点目で確認された場合は、その3点目以降を中心へ吸着する。確認前の2点は既に記録済みの生座標のままとし、過去行を更新しない。退出も3点目で確認された時点から生座標へ戻す。この規則により、記録時以後に履歴を書き換えず、実装の再起動安全性を保つ。

有効な場所が0件になる、または契約状態・並び順の変更で現在の吸着先が無効になった場合は、その位置更新から直ちに未吸着へ戻す。以後は新しい有効な場所集合で入場判定をやり直す。

### 保存処理への組み込み

位置情報1点の処理順は次のとおりとする。

```text
OS位置情報
  → 生座標のLocationPointへ変換
  → 現在有効な滞在場所とランタイム吸着状態で有効座標を解決
  → 有効座標でVisited Gridを更新
  → 有効座標で保存間引き・区間距離を判定
  → 生座標と有効座標を同じlocation_points行へ保存
  → 有効座標で日別距離を加算
```

精度・時刻の検証は生GPSの観測値を使い、位置差を使う保存間引き、区間距離、Visited Gridは有効座標を使う。これは吸着中のGPS揺れが距離やエリアを増やすことを防ぐためである。保存対象外の点についても、既存どおりVisited Gridの補間処理を行うが、有効座標を渡す。

DBへ保存する点の有効座標は、生座標と同じ場合も明示して保存する。これにより、「補正を適用しなかった」という記録時の決定を明確にし、読取側のフォールバックは旧データだけに限定できる。

## 座標の利用規則

| 利用箇所 | 使用座標 |
| --- | --- |
| 日別・月次の距離 | 有効座標（旧データは生座標） |
| Visited Grid | 記録時の有効座標 |
| アプリ内の通常ルート地図 | 有効座標（旧データは生座標） |
| 共有画像、GIF、月次レポート | 有効座標を非表示範囲で分割したもの |
| GPXエクスポート | 生座標 |
| GPXインポート | 生座標を有効座標として保存し、吸着しない |
| 現在地アイコン | OSから得た現在の生座標 |

距離の再計算が必要な既存の集計ロジックも、共通の有効座標変換を通す。集計・描画が個別に `latitude` / `longitude` を直接参照する新規コードは禁止し、既存箇所は実装時に検索して置換する。

## 共有時のプライバシー範囲

### 対象成果物

共有によって外部へ出す地図ルートを持つすべての成果物に適用する。

- 日別記録詳細の共有画像
- 日別記録のアニメーションGIF（プレビューを含む）
- 月次レポートの画像・動画

アプリ内の通常の地図表示、端末内SQLite、GPXエクスポートには非表示範囲を適用しない。

### 分割アルゴリズム

共有対象の有効座標列を時系列順に走査し、有効な滞在場所のうち少なくとも1つの非表示半径内にある点を除外する。`含める`（`privacy_radius_meters = NULL`）は除外対象にしない。点が半径境界上にある場合も除外する。

可視点だけを単一の `Polyline` へ渡してはいけない。半径内に入る点を見つけた時点で現在のセグメントを閉じ、次の可視点から新しいセグメントを開始する。2点未満のセグメントは描画しない。

```text
可視 A → 可視 B → 非表示 C → 非表示 D → 可視 E → 可視 F

描画: [A, B] と [E, F]
禁止: [A, B, E, F] を1本の線として描く
```

この処理は `privacyRouteSegments.ts` の純粋関数に置く。既存の異常速度・大きな時刻間隔によるルート分割とも組み合わせ、両方の分割理由を守る。適用順は、まず既存の異常ギャップで区切り、各区間からプライバシー範囲でさらに区切る。

月次レポートが有効なルート点を持たなくなっても、距離・日数などの集計は表示する。地図部分は既存の空状態表示へフォールバックし、共有処理を失敗させない。

## UIとナビゲーション

### 設定一覧

設定画面に「滞在場所」行を追加し、子画面の一覧へ遷移する。リスト主体の既存設定UIに合わせ、カード型UIにはしない。

一覧では名称、共有時の範囲、優先順を表示する。無料版・解約中で2件目以降が存在する場合は、非先頭行に「Plusで有効」の補助文言を表示する。先頭は「現在有効」と表示する。並べ替え操作の説明として「先頭の場所を使用します」を明示する。

無料版で1件登録済みのときに追加操作を選ぶと、滞在場所の複数登録を説明した既存のPlus購入導線へ進める。削除・編集・並べ替えは解約中も行える。Plusから無料版への変化は、一覧の有効表示を契約状態に応じて即時更新する。

### 追加・編集

追加・編集は共通の子画面とする。入力項目は名称、中心位置、共有時の非表示範囲である。

- 地図の中央に固定マーカーを置き、地図のパン・ズームで中心位置を選択する
- 現在地を初期中心として使える場合は使うが、現在地取得を必須にしない
- 逆ジオコーディングや住所の自動入力は行わない
- 保存前に名称の空文字、座標の有限値、許可されない半径値を検証する
- 子画面は右から入り、戻る際は左へ戻る。iOSでは左端スワイプバックを使えるようにする

新規画面のルートは薄いラッパーとし、UI実体は `src/ui/components/`、状態・操作は `AppStateProvider` を経由する。ユーザー向け文言は `appText.ts` に集約する。

## エラー処理と整合性

- 滞在場所の読み込み失敗時は吸着と共有時の非表示範囲を適用しない。生座標の記録・共有を継続し、エラーを記録する
- 滞在場所の保存・並べ替えに失敗した場合は一覧をDBの状態へ再読込し、成功していない表示順を残さない
- 吸着判定の入力が不正な座標の場合は吸着せず、生座標の既存検証に委ねる
- 記録中に滞在場所の更新、削除、並べ替え、契約状態変更が起きた場合は、次の位置更新から最新の有効集合を使う
- 非表示ルートの生成に失敗しても、共有成果物に生ルートをフォールバックしてはいけない。共有を中止してエラーを通知する
- 半径内の点をすべて除外した共有では、ルートなしとして成果物を作成する。位置情報を露出させる代替描画は行わない

## テスト方針

テスト名は日本語で記述する。OS GPS、実際のMapViewキャプチャ、RevenueCat通信はモックし、座標変換・状態遷移・DB操作・UI操作を分離して検証する。

### 純粋ロジック

- `resolveActiveStayPlaces`: Plusでは全件、無料版・解約中では並び順先頭だけ、同順位時の安定順序
- 非表示半径の値変換と不正値拒否
- 吸着状態遷移: 入場・退出の各2点までは状態を変えず3点目で変わること、境界50m、候補切替、重複範囲、無効化時の解除、再起動相当の初期状態
- 有効座標のフォールバック: 新規行、旧行、片方だけの不正な有効座標
- 非表示ルート分割: 範囲内点の除外、線分非接続、境界、複数滞在場所、`含める`、既存の異常ギャップとの組合せ、全点非表示

### リポジトリと記録セッション

- migrationが既存DBを壊さずテーブル・列・インデックスを追加すること
- 滞在場所の登録、更新、削除、並べ替えのSQLとトランザクション
- GPS記録が生座標と有効座標を保存すること
- 吸着中の区間距離、保存間引き、Visited Gridが有効座標を使うこと
- GPXインポートが吸着resolverを呼ばず、生座標を有効座標として保存すること
- GPXエクスポートが有効座標ではなく生座標を出すこと

### UI・統合

- 設定から滞在場所一覧、追加・編集画面へ遷移できること
- 無料版の1件目追加、2件目追加時のPlus導線、並べ替えによる有効先の変更
- Plus解約・再契約で有効表示と使用対象が切り替わり、レコードが削除されないこと
- 固定中心マーカーの地図操作で保存座標が変わること
- 共有画像、GIF、月次レポートが複数のPolylineセグメントを描画し、非表示区間をまたいで結ばないこと

実機ではiOSとAndroidの両方で、GPSが半径境界を出入りする記録、解約状態からの再契約、共有画像/GIF/月次レポートの目視確認を行う。

## 非対象

- 既存GPSログの一括吸着・距離・エリア再計算
- GPXインポートへの吸着適用
- GPXエクスポートの座標変更
- 滞在場所名の住所自動解決、逆ジオコーディング
- サーバー同期、複数端末間の滞在場所共有
- 滞在場所ごとに異なる吸着半径・連続点数を設定するUI
