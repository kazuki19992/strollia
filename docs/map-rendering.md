# マップ表示仕様

## 1. 基本方針

Strollia では、保存したGPSログをマップ上にプロットし、位置情報ポイントを線でつないで移動ルートとして表示する。

表示対象は以下とする。

- 1日単位の移動ルート
- from-to で指定した任意範囲の移動ルート
- これまでの全記録を重ねた全履歴マップ
- 任意機能として、ジオタグ付き写真を重ねたマップ

## 2. マップライブラリ方針

初期候補は `react-native-maps` とする。

理由は以下である。

- Expoで利用しやすい
- iOS / Android の両方に対応している
- iOSではApple Maps、AndroidではGoogle Mapsを利用できる
- `Polyline` によりGPSログを線として描画しやすい

## 3. 地図プロバイダー方針

### 3.1 第一候補

初期実装では、OS標準に近い地図表示を第一候補とする。

- iOS: Apple Maps
- Android: Google Maps

この構成はユーザーに馴染みがあり、React Native / Expoで扱いやすい。

### 3.2 OpenStreetMapの扱い

OpenStreetMapは地図データ自体は自由に利用できるが、OpenStreetMap Foundation の標準タイルサーバーは容量に限りがあり、利用ポリシーを守る必要がある。

そのため、初期仕様では OpenStreetMap 標準タイルサーバーの直接利用を本番アプリの前提にはしない。

OpenStreetMapを利用する場合は、以下のいずれかを検討する。

- 利用規約に合うOSM系タイルプロバイダーを利用する
- 必要な範囲のタイルをユーザー操作でキャッシュまたは保存する
- 将来的に自前タイルサーバーを用意する
- オフライン地図対応が必要になった段階で別ライブラリを検討する

ただし、自前タイルサーバーは運用費が発生するため、初期方針とは相性が悪い。

## 4. 描画仕様

### 4.1 GPSポイント表示

GPSログの各点は、必要に応じてマップ上にプロットできる。

ただし、常に全点をマーカー表示すると視認性とパフォーマンスが悪くなるため、通常表示ではルート線を中心とする。

メインマップでは開始地点・最新地点のマーカーは表示しない。全履歴を俯瞰するときの視認性を優先する。

### 4.2 ルート線表示

品質判定後に保存したGPSポイントを時系列順に並べ、隣接する accepted 点同士を線でつないでルートとして描画する。

描画には `Polyline` 相当の機能を使用する。

メインマップのルート線は保存済み accepted 点から `RouteSegment` を生成し、時間ギャップや不自然な区間速度がある境界では `Polyline` を分割する。描画用の簡略化は segment ごとに適用する。

保存前品質判定で落としきれなかった境界ケースや過去データに備え、描画時の `RouteSegment` 分割は保険として残す。通常は保存済み accepted 点だけで安定した軌跡を再現する。

表示項目は以下を想定する。

- ルート線
- 必要に応じた中間ポイント
- 記録が途切れた区間の表現

### 4.3 記録途切れ区間

GPS取得が長時間途切れた場合、単純に線でつなぐと実際には移動していない経路が描かれる可能性がある。

そのため、以下の条件に該当する場合は線を分割することを検討する。

- 前後の記録点の時間差が一定以上ある
- 前後の距離が不自然に大きい
- 位置精度が低い点が連続している

閾値は詳細仕様で決定する。

### 4.4 メインマップ下部メーター

メインマップ下部には、速度リング、距離情報、画面遷移ボタンをまとめたダッシュボードを置く。

- 左側の速度リングに accepted 点間の距離と記録時刻から求めた現在速度を `km/h` で表示する
- 速度リングはアナログスピードメーターとして、速度帯の上限に対する現在速度に応じて円周ゲージを進める
- 速度リングは raw map event speed を直表示せず、保存品質判定を通った点列と整合する速度を使う
- 速度帯は low-speed が `30 km/h` 未満、車相当が `30 km/h` 以上 `150 km/h` 未満、高速移動が `150 km/h` 以上とする
- 停止状態はテーマカラーを明るくした色、歩行は緑寄りの青、車相当はオレンジ、高速移動はピンクを使う
- 速度リングと情報帯は半透明背景をSVGの単一パスで成形し、接合部だけ背景色が濃くならない一体形状にする
- 情報帯には通算距離 `ODO`、今日の移動距離 `TODAY`、現在地の市区町村と副地域名を並べる
- 情報帯は `ODO` が100万km整数部 + 小数点以下2桁、`TODAY` が4桁整数部 + 小数点以下2桁を表示できる幅配分にする
- 距離値は整数部の桁数が変わっても右端が動かない右寄せ表示とし、市区町村名は最大6文字程度を表示できる地名領域を確保する
- 下段には `日ごとの記録`、`実績`、`レポートを見る`、`設定`、`マップの表示` のボタンを置く
- `マップの表示` では標準マップと航空写真を切り替え、マップ上の写真表示設定も切り替えられる
- 数値部分はDSEG系フォントを使い、地図上でも一目で読めるようにする
- 距離の小数点以下2桁は数字部分のみ整数部より小さくし、小数点は整数部と同じ大きさで下揃え表示する
- パネルとボタンは `#333333` の80%背景と影を持つ要素として扱う
- 現在地ボタンはダッシュボード上部に置き、現在地アイコンは常に白で表示する

### 4.5 メインマップ上部オーバーレイ

現在地名とマップ操作導線は下部ダッシュボードへ集約する。

- メインマップ上部には固定の市区町村パネル、移動モードパネル、メニューボタンを置かない
- 上部は地図表示を優先し、OSステータスバー、コンパス、開発フラグバナーなど必要な表示だけを残す

## 5. 日単位マップ

日付を選択すると、その日の 0時〜24時 のGPSログを表示する。

表示内容は以下とする。

- 対象日のルート線
- 開始地点マーカー（緑、`開始` ラベル）
- 最新地点マーカー（赤系、`最新` ラベル）
- 記録開始時刻
- 記録終了時刻
- 推定移動距離
- 記録点数

## 6. 範囲指定マップ

from-to で指定した範囲のGPSログを表示する。

範囲指定UIと連動し、A点・B点を動かすたびに、対象範囲のルートをマップ上でプレビューできることを目指す。

## 7. 全履歴マップ

全履歴マップでは、これまで保存されたすべてのGPSログをマップ上に描画する。

目的は、ユーザーがこれまで歩いた場所・移動した場所を俯瞰できるようにすることである。

想定する表示方法は以下である。

- 全期間のルート表示
- 日付、月、年などによる色分け
- 期間フィルター
- 記録密度の高い場所の視覚化
- 大量データ時の間引き表示

## 8. 写真ジオタグ表示（任意機能）

ユーザーが写真ライブラリへのアクセスを許可し、写真表示を有効にした場合、ジオタグ付き写真をマップ上に表示する。

表示はオン/オフ可能とする。

表示方法は以下とする。

- 写真のGPS座標にマーカーを表示する
- マーカーは小さい四角い吹き出しとして表示し、その中にサムネイルを表示する
- 近接する複数写真は1つの吹き出しにまとめ、右下に `+n` の件数バッジを表示する
- 単体写真のマーカーをタップすると、写真を全画面プレビューで表示する
- 複数写真の吹き出しをタップすると、吹き出し内に写真グリッドを表示する
- グリッド内の写真をタップすると、写真を全画面プレビューで表示する。10枚以上ある場合は9枚単位のページとして横スワイプで閲覧する
- 表示中の日付またはfrom-to範囲に撮影された写真のみ表示できるようにすることは将来検討とする
- ジオタグがない写真は表示しない

初期実装では、設定画面で写真表示をONにした場合のみ全履歴マップに表示する。

## 9. パフォーマンス方針

GPSログは長期間蓄積されるため、マップ描画の負荷を抑える必要がある。

初期方針は以下とする。

- 表示範囲に必要なデータだけSQLiteから取得する
- 期間指定時は `recorded_at` で範囲検索する
- 日別表示時は `local_date` で取得する
- 全履歴表示では点数が多い場合に間引きを行う
- ズームレベルに応じて描画点数を調整する
- 写真マーカーは表示範囲に応じた距離判定で近接写真をクラスタリングし、拡大率に応じてクラスタ範囲を上下させる
- 生ログとは別に描画用ルート座標を生成する
- 描画用ルートはDouglas-Peucker法で形状を保ちながら簡略化する
- メインマップでは現在の表示範囲付近の描画点だけを `Polyline` に渡す

## 10. 無料利用についての考え方

地図表示は「アプリ側のサーバー費用を発生させない」ことを重視する。

ただし、地図SDKやタイルプロバイダーには、それぞれ利用規約、APIキー、無料枠、制限がある。

初期判断としては以下とする。

- iOSではApple Mapsを優先する
- AndroidではGoogle Mapsを優先する
- OpenStreetMapは候補として残すが、標準タイルサーバーの本番利用は慎重に扱う
- 商用公開やユーザー増加を想定する段階で、地図プロバイダーの料金・利用規約を再確認する

## 12. 現在地追従

メインマップでは、通常は現在地に追従する。

ユーザーが地図をスワイプして現在地中心から離れた場合、現在地ボタンを表示する。表示・非表示は0.5秒のフェードアニメーションとする。

現在地ボタンを押した場合、または地図中心が現在地付近に戻った場合、再び現在地追従を有効にする。

現在地ボタンには `@expo/vector-icons` の `AntDesign/aim` を使用する。

## 13. 地図UIオーバーレイ

メインマップ操作は下部ダッシュボードへ集約する。日別ログ、実績、レポート、設定は下段ボタンから開き、地図種別と写真表示は `マップの表示` パネルから切り替える。

画面切り替え、地図種別切り替えなどの主要操作では、短いアニメーションと軽いタプティックフィードバックを入れる。

Apple Maps の法的表示やiOS標準コンパスがアプリのオーバーレイに隠れないよう、`mapPadding` と `legalLabelInsets` を設定して安全な余白を確保する。

## 14. 描画軽量化

GPSログの保存用データと描画用データは分けて扱う。保存用データはSQLiteに保持し、マップ表示ではDouglas-Peucker法で簡略化した描画用座標を使う。初期許容誤差は徒歩ログ向けに10mとする。

メインマップでは `onRegionChangeComplete` で現在の表示範囲を保持し、表示範囲に近い `RouteSegment` だけを `Polyline` に渡す。これにより、全履歴表示でズームアウト・パンした場合の描画負荷を抑える。

## 15. 日別移動リプレイ

日別移動リプレイでは、選択した1日のGPSログを時系列で再生する。

初期MVPでは、日別ログ画面からリプレイ画面へ遷移し、シークバーで指定した時刻までのルート線を描画する。

表示内容は以下とする。

- 対象日の最初のGPSポイントから、シークバーで指定した時刻までのルート線
- 指定時刻時点の現在位置マーカー
- 現在のリプレイ時刻
- 再生/一時停止ボタン
- シークバー

該当時刻がGPSポイントの間にある場合、初期MVPでは直前のGPSポイントを現在位置として扱う。線形補間は将来改善とする。

初期表示時は対象日のルート全体が入るよう地図をフィットする。自動再生中の地図追従は必須にせず、ユーザーがパン/ズームしてもリプレイ自体は継続する。

この機能は Strollia Plus 候補とし、Plus無効時はリプレイ画面への遷移前にPlus案内を表示する。
