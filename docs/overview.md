# すとろりあ / Strollia 概要仕様

## 1. アプリケーション概要

「すとろりあ」（英語名: `Strollia`）は、React Native + Expo で開発するモバイル向けGPSロガーアプリケーションである。

スマートフォンのGPS位置情報を継続的に読み取り、日単位で移動履歴を記録する。記録された位置情報はアプリ内のマップ上で確認でき、必要に応じて GPX または KML ファイルとしてエクスポートできる。

## 2. 名称

### 日本語名

すとろりあ

### 英語名

`Strollia`

### 名前の由来

`Strollia` は、英語の `stroll`（ぶらぶら歩く、散歩する）と、ラテン語由来の語尾 `-ia`（場所、状態、概念を示す）を組み合わせた造語である。

散歩や移動の記録が集まり、自分だけの「歩いた場所・過ごした状態・移動の概念」が形になっていくアプリ、という意味を込める。

## 3. 目的

このアプリケーションの目的は、ユーザーの日々の移動履歴を自動的に記録し、あとから見返したり、外部ツールで利用できる形式に書き出したりできるようにすることである。

主な利用シーンは以下を想定する。

- 日々の散歩、移動、旅行の記録を残す
- 1日ごとの移動ルートをマップ上で確認する
- これまでの全記録をまとめてマップ上に表示し、自分の行動範囲を俯瞰する
- 記録したGPSログを GPX / KML としてエクスポートし、地図アプリ、GISツール、動画編集、アーカイブ用途などで利用する
- GPX / KML をインポートし、バックアップ復元や外部ログの取り込みに利用する
- 任意機能として、ジオタグ付き写真をマップ上に重ねて表示する

## 4. 基本コンセプト

Strollia は「記録を意識しすぎず、あとから気持ちよく振り返れるGPSロガー」を目指す。

アプリはバックグラウンドでも位置情報を記録し、0時から24時までを1日としてログを管理する。ユーザーは日ごとのログを確認できるほか、全期間のログをひとつのマップ上に重ねて表示できる。

エクスポートでは、単純な1日単位の出力だけでなく、開始日時と終了日時を指定した任意範囲の出力にも対応する。範囲指定は、動画編集におけるA点・B点指定のように、シークバー形式で直感的に選択できるUIを目指す。

## 5. 対象プラットフォーム

- iOS
- Android

開発基盤は以下とする。

- React Native
- Expo

## 6. 主な機能

### 6.1 GPSログ記録

スマートフォンのGPSを利用し、位置情報を継続的に記録する。

記録対象の主な情報は以下を想定する。

- 緯度
- 経度
- 取得日時
- 高度
- 速度
- 方位
- 位置精度

高度、速度、方位、位置精度は端末やOSから取得できる場合に保存する。

### 6.2 日単位のログ管理

0時から24時までを1日としてGPSログを管理する。

日付の区切りはユーザーの端末タイムゾーンに従うことを基本とする。

### 6.3 日ごとの記録表示

ユーザーは任意の日付を選択し、その日の移動履歴をマップ上で確認できる。

表示内容は以下を想定する。

- 移動ルートのライン表示
- 開始地点と終了地点の表示
- 記録点の概要
- 記録時間帯
- 移動距離などのサマリー

### 6.4 全記録のマップ表示

日ごとの記録だけでなく、これまでに記録したすべてのGPSログをマップ上に描画して確認できる。

この表示では、ユーザーの移動履歴全体を俯瞰できることを重視する。

想定する表示方法は以下である。

- 全期間のルートをまとめて表示
- 日付ごと、月ごと、年ごとなどで色分け
- 表示対象期間の絞り込み
- 記録量が多い場合でも操作しやすい描画方式

### 6.5 GPX / KML エクスポート

記録したGPSログは、外部で利用しやすい形式として GPX または KML ファイルにエクスポートできる。

また、バックアップ復元や外部ログ取り込みのため、GPX / KML ファイルのインポートにも対応することを目指す。

対応するエクスポート単位は以下とする。

- 1日単位
- 日付・時刻範囲指定（from-to）

### 6.6 日付・時刻範囲指定エクスポート

ユーザーは開始日時と終了日時を指定して、任意範囲のGPSログをエクスポートできる。

範囲指定UIは、動画編集ソフトにおけるA点・B点指定のような直感的な操作感を目指す。

想定するUIは以下である。

- タイムラインまたはシークバー上にログの存在範囲を表示
- A点を開始位置、B点を終了位置として指定
- 指定範囲の開始日時・終了日時をリアルタイム表示
- 指定範囲のルートをマップ上でプレビュー
- 指定範囲のみを GPX / KML として出力


### 6.7 写真ジオタグ表示（任意機能）

写真ライブラリへのアクセス権限をユーザーが許可した場合、ジオタグ付き写真をマップ上に表示できるようにすることを検討する。

写真は撮影日時とGPSメタデータをもとに、表示中の日付・時刻範囲と照合する。ジオタグが存在する写真のみを表示対象とし、ジオタグがない写真は表示しない。

この機能は必須機能ではなく、実装難易度やOS制約が大きい場合は初期リリースから外してよい。

## 7. データの考え方

GPSログは時系列の位置情報として保存する。

基本的なデータ構造は以下を想定する。

- 記録セッション
- 記録日
- 位置情報ポイント
- エクスポート履歴

初期段階では日単位で扱いやすい構造を優先しつつ、将来的に大量データを扱えるようにする。

## 8. 非機能要件の方向性

### 8.1 バッテリー消費

GPSを継続利用するため、バッテリー消費を抑える設計が重要である。

記録頻度、位置精度、バックグラウンド動作の設定は、用途に応じて調整できるようにすることを検討する。

### 8.2 プライバシー

GPSログは個人の行動履歴そのものであるため、プライバシーを最重要事項として扱う。

初期方針として、記録データはすべて端末内にローカル保存する。サーバーは用意せず、ローカルDBとして SQLite を使用する方針とする。重大な例外やクラッシュの解析にはproductionビルドのみSentryを利用するが、送信項目は `docs/architecture.md` のSentry送信項目に限定し、GPSログ本体、写真ジオタグ、座標値は送信しない。developmentビルドとpreviewビルドではSentry送信を行わない。その他の外部送信やクラウド同期を行う場合は、将来機能として扱い、明示的なユーザー操作または設定を必要とする。

### 8.3 パフォーマンス

長期間のGPSログを扱うため、マップ表示や全履歴描画ではパフォーマンスに配慮する。

必要に応じて、以下のような最適化を検討する。

- 表示ズームレベルに応じた点の間引き
- 日付・期間単位での遅延読み込み
- 全履歴表示用の簡略化データ生成
- 大量ログ描画に適したマップレイヤーの利用
