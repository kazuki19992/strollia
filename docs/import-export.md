# インポート・エクスポート仕様

## 1. 基本方針

Strollia はGPSログをローカル保存するため、ユーザーが自分のデータを外部ファイルとして取り出し、必要に応じて再度取り込めるようにする。

この仕様では、以下を扱う。

- GPXエクスポート
- KMLエクスポート
- GPXインポート
- KMLインポート
- バックアップ用途のインポート・エクスポート

## 2. エクスポート機能

記録済みGPSログを、外部ツールで利用できる形式として出力する。

対応形式は以下とする。

- GPX
- KML

対応する出力範囲は以下とする。

- 1日単位
- 日付・時刻範囲指定（from-to）
- 全期間エクスポート

### 2.1 全期間エクスポートの実装

全期間エクスポートは、単一GPXファイル内に日別ごとの `<trk>` 要素を複数持つ構造で実装されている。従来のアプローチのように全ポイント数をメモリに読み込むのではなく、`shareAllLogsAsGpx()` 関数が日別にポイントを段階的に取得し、`expo-file-system/legacy` の `append: true` オプションを使ってディスク上のファイルへ逐次追記する。この方式により、アプリメモリ使用量は1日分のデータに有界化され、記録年数が長い端末でもメモリ制約に影響されない。

生成されるGPXファイルの構造は各日を独立した `<trk>` 要素で表現し、複数日のデータはこれらのトラック要素の集合として保持される。既存のGPXインポータは `<trkpt>` 要素を `<trk>` の深さに関わらず収集するため、このエクスポート形式はインポータと往復互換(エクスポート→インポート)を維持している。

### 2.2 滞在場所補正との関係

GPS記録では、滞在場所周辺の揺れを抑えるために表示・距離・エリア用の有効座標を別に保存する場合がある。ただしGPXはユーザーの元データを取り出す用途のため、常に生座標（`latitude` / `longitude`）を出力する。有効座標や吸着した滞在場所IDはGPXへ出力しない。

## 3. インポート機能

ユーザーは外部ファイルからGPSログを取り込み、Strollia のローカルDBに保存できる。

主な目的はバックアップ復元である。

対応形式は以下とする。

- GPX
- KML

## 4. インポート時の基本動作

インポート時は、ファイル内の位置情報ポイントを解析し、Strollia の `location_points` に保存する。

GPXインポートは過去の観測記録として扱い、現在の滞在場所設定で吸着判定を行わない。取り込んだ生座標を、そのまま有効座標として保存する。

取り込み対象の主な情報は以下とする。

- 緯度
- 経度
- 記録日時
- 高度
- 速度
- 方位
- 位置精度

形式によって取得できない項目は `NULL` として扱う。

## 5. 重複データの扱い

バックアップ復元では、同じファイルを複数回インポートする可能性がある。

そのため、重複登録を避ける仕組みを持つ。

初期方針として、以下の組み合わせが一致する位置情報ポイントは重複候補とする。

- `recorded_at`
- `latitude`
- `longitude`

重複候補が見つかった場合の動作は以下から選べるようにすることを検討する。

- スキップする
- 上書きする
- 別データとして追加する

初期実装では「スキップする」をデフォルトとする。

## 6. インポートプレビュー

インポート前に、ファイル内容の概要を表示する。

表示内容は以下を想定する。

- ファイル名
- ファイル形式
- 記録開始日時
- 記録終了日時
- 位置情報ポイント数
- 推定移動距離
- 既存データとの重複候補数

ユーザーは内容を確認したうえで取り込みを実行する。

取り込みは100ポイントごとのトランザクションに分割し、チャンク間に短い待機を挟んで実行する。GPS記録中でもバックグラウンドの書き込みを長時間ブロックしないためである。

さらに、インポート実行中に受信したGPS位置情報はDBへ書き込まずメモリへ退避し、インポート完了後(失敗時も含む)に通常の保存規則でまとめて取り込む。インポートを優先しつつ、記録中の位置情報を失わないためである。途中で失敗した場合は取り込み済みの部分が残るが、既存データ優先(INSERT OR IGNORE)のため再インポートで重複せず安全にリトライできる。

## 7. バックアップ用途

バックアップ用途では、GPX / KML だけでは Strollia 固有の情報を完全には復元できない可能性がある。

そのため、将来的には Strollia 独自のバックアップ形式を検討する。

候補は以下である。

- SQLiteデータベース全体のエクスポート
- JSON形式のアプリ内バックアップ
- ZIP形式でGPSログ、設定、派生データをまとめるバックアップ

初期仕様では GPX / KML のインポート・エクスポートを優先する。

## 8. ファイル操作

Expo環境では、ファイルの読み書きに `expo-file-system` を利用することを検討する。

ファイル選択、共有、保存先指定については、各OSの標準UIを利用する。

## 9. エラー処理

インポート時には以下のエラーを想定する。

- ファイル形式が未対応
- ファイルが壊れている
- GPSポイントが含まれていない
- 記録日時が存在しない
- 端末ストレージ容量が不足している
- インポート途中でアプリが終了した

エラー時は、可能な限り取り込み前の状態を保つ。
