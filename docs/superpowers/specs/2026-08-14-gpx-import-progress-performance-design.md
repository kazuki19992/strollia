# GPX Import Progress and Performance Design

## Purpose

大容量GPXの取り込み中に、低性能なAndroid端末でも処理開始を明確に示し、アプリ側の操作競合を防ぐ。あわせて #147 の要件として、待機中の進捗ダイアログへ通算距離（ODO）をDSEG数値フォントで表示する。

## Goals

- GPXインポートを開始した直後から、アプリ内の重複操作・画面遷移・データ削除を防ぐ。
- OS標準のファイルピッカーは最前面かつ操作可能なまま維持する。
- ファイル選択後は、解析・保存・再読み込みの全期間で閉じられない進捗ダイアログを表示する。
- 進捗バーの下に中央揃えで `ODO 123.45km` 形式の通算距離を表示する。数値部だけ既存マップと同じDSEGフォントを使う。
- 大容量ファイルのSQLite書き込みにある不要な待機と、visited cell更新の細かなSQLite往復を減らす。
- 100m visited gridの意味、既存データ優先、バックグラウンドGPS記録の安全性を保つ。

## Non-goals

- ファイルピッカーのUIやOS側のコピー時間そのものを変更しない。
- GPXのストリーミング解析・ネイティブワーカー化は今回行わない。
- ODOの表示をリアルタイムの進捗率へ変換しない。表示値はインポート開始時点の通算距離とする。
- 既存のGPX取り込み仕様、重複判定、訪問セル補間ルールを変更しない。

## UX Flow

1. ユーザーが設定画面でGPXインポートを押す。
2. 実績に関する既存の注意ダイアログを確認する。
3. OK直後にアプリ側のブロッキング状態を有効にし、OSファイルピッカーを開く。
   - OSファイルピッカーは最前面で通常どおり選択・キャンセルできる。
   - 背面のStrolliaは操作不能とする。
4. ファイルが選択されたら、グローバル進捗ダイアログを表示して1フレーム描画後にファイル読込・解析を開始する。
5. 保存・再読み込み・地図更新中も同じダイアログを維持する。
6. 成功・キャンセル・エラーのいずれでもブロッキング状態を解除する。

## Progress Dialog

- `GpxImportProgressDialog` は処理段階を受け取り、本文を「ファイルを読み込んでいます…」「GPXを解析しています…」「GPXを保存しています…」のように更新する。
- 進捗バーの下に、横方向中央揃えで ODO を表示する。
- `ODO` と `km` は通常フォント、整数部・小数点・小数部は `NUMERIC_DISPLAY_FONT`（DSEG）とする。
- 距離の整形はマップの `formatDistanceKilometers` と同一の小数第2位表記を利用する。
- ODOは取り込み開始前の `distance` を表示する。途中でDBを再計算しないため、表示のための追加コストを発生させない。

## State and Integration

- `isImportingGpx` は設定行の二重タップ防止を引き続き担当する。
- `isProcessingGpxImport` は注意確認後から処理のfinallyまで、進捗ダイアログ表示とアプリ側の操作ロックを兼ねて担当する。状態を分けずに一貫して保持することで、ファイルピッカー表示までの空白時間を作らない。
- `GpxImportProgressStage` をProviderで管理し、ダイアログへ渡す。
- OSファイルピッカーの呼び出しは、UIロックstateの反映後に2フレーム譲ってから開始する。これによりAndroidで背面操作可能な空白時間を作らず、iOSのネイティブModal遷移とも競合しにくくする。

## Performance Changes

### Remove idle time between import chunks

GPXインポート優先モード中は通常GPS書き込みをバッファしている。そのため、各100件チャンク間の固定50ms待機は不要である。待機を削除して、次チャンクを直ちに開始する。

### Batch visited-cell upserts

各ポイントごとにvisited cellをSQLiteへupsertすると、1点ごとに複数回のJS-to-native呼び出しが発生する。チャンク内で開放対象セルを日時とともに蓄積し、最後にセルID単位で集約してupsertする。

- `first_visited_at` は最小時刻、`last_visited_at` は最大時刻、`visit_count` は同一セルが開放された回数を保つ。
- `source` と100mセルID、既存の高速移動補間規則は変更しない。
- 同一トランザクション内に保持し、途中チャンク失敗時はそのチャンク全体がロールバックされる。

## Verification

- Provider統合テストで、注意確認後にUIロックが有効になり、キャンセル・成功・失敗で解除されることを確認する。
- ダイアログ単体テストで、ODOのラベル、DSEG数値部、中央揃えを確認する。
- Repositoryテストで、チャンク間の待機がなく、集約したvisited cellの回数と最初・最後の訪問日時が正しいことを確認する。
- `npm run typecheck`、対象Jest、`npm run lint`、`npm test -- --runInBand` を実行する。
- Galaxy A25 5GとiOS実機で、大容量GPXの選択直後に背面操作ができないこと、ファイルピッカーが操作可能であること、ODO表示、完了までの時間を手動確認する。iOSでは進捗ダイアログの表示直後にもファイルピッカーが正常に開くことを確認する。位置履歴・ファイル内容はログ出力しない。
